# golden: generator=ghidorah-base::catalog::errors_markdown version=1
This file lists the frozen code catalogs of ghidorah (design Section 10.8, ADR-0002).
The test `ac_026_errors_doc_golden` makes this file from the enums of `ghidorah-base`.
Do not edit this file by hand. Run the test with `GHIDORAH_BLESS=1` to write it again.

Code numbers never change. No code uses a reserved number.
A message can hold placeholders such as `{field}`. The server fills them before output.
An error result takes the plain hint when the hint names a `next[0]` or candidates that the result does not hold.

## Repair classes

| Class | Meaning |
|---|---|
| R | The result holds the complete corrected call in next[0]. |
| R* | The class is R only when the fix is mechanical. Else the result has no repair call. |
| C | The candidates hold the choices. No client picks one by rule. |
| H | The result holds a helper call in next[0], for example tool_search. |
| N | No mechanical repair exists. |

## Diagnostic codes

A loader diagnostic or a C parser error has one of these codes.

| Num | Code | Message | Hint |
|---|---|---|---|
| 1 | `E_OOB` | A read goes past the end of its buffer or its table. | The parser skips the item or stops the walk. |
| 2 | `E_OVERFLOW` | An address or a size computation overflows 64 bits. | The parser skips the item. |
| 3 | `E_BAD_MAGIC` | The magic value of a header or a record is wrong. | Load the file as a raw blob when the format is not ELF or PE. |
| 4 | `E_LIMIT` | A count is above its limit. The parser keeps the clamped count. | The limits table of the design gives each cap. |
| 5 | `E_LOOP` | A walk does not advance, or it comes back to a visited item. | The parser stops the walk. |
| 6 | `E_BAD_ALIGN` | A value does not have the alignment of its type. | The parser skips the item. |
| 7 | `E_BAD_ENTSIZE` | A table entry size does not match its type. | The parser skips the table. |
| 8 | `E_UNSUPPORTED_RELOC` | The relocation type is not in the MVP set. | The parser skips the entry and reports each type once. |
| 9 | `E_CFA_OPCODE` | A CFA instruction has an unknown opcode. | The parser stops the instructions of the FDE. |
| 10 | `E_OVERLAP` | Two PE sections overlap. The later section replaces the overlapped part. | The memory map keeps the later section. |
| 11 | `E_SYNTAX` | The C text has a syntax error. | The error gives the location and the expected tokens. |
| 12 | `E_UNKNOWN_TYPE` | The C text names a type that does not exist. | The candidates hold the closest type names. |
| 13 | `E_INCOMPLETE_BY_VALUE` | A record holds an incomplete type by value. A record cannot hold itself by value. | Use a pointer to the type. |
| 14 | `E_CONST_EXPR` | A constant expression does not evaluate to an integer. | Use an integer constant. |
| 15 | `E_UNSUPPORTED` | The C text uses a feature outside the MVP: bit-fields, attributes, declspec or pragma pack. | Remove the feature from the C text. |
