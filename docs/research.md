# ghidorah research report

Date: 2026-10-16. Status: input to the design and planning phase.

## 1. Purpose

- This report gives the research base for ghidorah. ghidorah is a pure-Rust software reverse engineering (SRE) framework in the spirit of Ghidra.
- Hard constraint 1: the build uses the Rust standard library only. There are zero third-party crates, also for JSON, CLI parsing and protocol code.
- Hard constraint 2: AI agents are the primary users. Every interface must be machine-readable, self-describing, stable and token-efficient.
- Each topic section gives findings with citation links, design implications and pitfalls. Section 4 merges the agent UX principles. Section 5 lists risks and open questions.
- "Measured" marks a local measurement on the build host (Linux x86-64, gcc 13.3, clang 18, binutils 2.42, rustc 1.97). A local measurement has no URL.
- Technical verbs in this report: parse, decode, disassemble, lift, demangle, fuzz, verify (Verus proof). Technical names: xref, basic block, thunk, stub, P-code, SSA, VA, RVA.

## 2. Summary of key decisions

- **Zero dependencies.** Write the JSON codec, CLI parser, SHA-256, PRNG, property-test harness, fuzz loop and MCP server in-house with std only.
- **One tool registry.** One table of tools (name, description, schemas, annotations, examples, handler) generates the CLI, the MCP stdio server, JSONL batch mode and `describe`.
- **Dual-era MCP.** Serve the legacy `initialize` handshake (2025-11-25, 2025-06-18) and the stateless 2026-07-28 revision (`server/discover`, per-request `_meta`).
- **Tool names.** Use lowercase `resource_verb` names with underscores, for example `func_get`. Do not use dots. Use about 15-25 merged tools, not one tool per API call.
- **Addresses.** Write every 64-bit value as a lowercase `0x` hex string. Accept hex, decimal strings, symbol names and `sym+0x10` expressions as input.
- **Errors.** JSON-RPC errors are for protocol faults only. A tool error is a result with `isError:true` and `{code, message, hint, candidates, valid_example, retryable}`.
- **Bounded output.** Every list has a small default limit, a hard cap, a cursor, `total`, `truncated` and a narrowing hint. Keep each result below about 40,000 characters.
- **Stable IDs.** `binary_id` comes from SHA-256 of the file. A function ID is its entry address. An IR op ID is `(addr, seq)`. IDs do not change after a rename.
- **Determinism.** Use `BTreeMap` or a sorted `Vec` on every output path. Analysis is single-threaded and orders work by (priority, analyzer name, address).
- **Program model.** One `Program` struct owns per-domain managers, as Ghidra `ProgramDB` does. Keep Ghidra numeric codes for references, comments, block permissions and analysis priorities.
- **Storage.** Keep the program in memory (`BTreeMap` per table). Persist content-addressed inputs, an append-only JSONL transaction journal and atomic snapshots.
- **Transactions.** Every mutation is one named command in one transaction. A nested abort poisons the whole transaction. Undo is logical (inverse operations). Every commit increments a revision.
- **Provenance.** Every name, type, signature, comment and reference has `{source, tx_id}`. Use Ghidra's SourceType priority lattice plus an AGENT source. Analyzers never overwrite a fact of higher priority.
- **Analysis engine.** Copy Ghidra's analyzer contract, trigger kinds and priority bands. Use a pending AddressSet per analyzer, a priority heap, event-driven re-queue, a fixpoint and a step budget.
- **Loaders.** ELF first, then PE and Mach-O. Lazy borrow-based parsers sit under one owned `Binary` model. Malformed tables give diagnostics, not fatal errors. One `Limits` struct holds all caps.
- **Decoders.** x86-64 has a structural length layer and a table-driven semantic layer. AArch64 and RV64IC use mask/value tables. All ISAs share one operand model. Canonical form and display text are separate.
- **IR.** Use a flat VEX-style lifted IR (L0) with `Get`/`Put` and a lazy flag thunk. Recover CFG, jump tables and stack pointer on L0 without SSA. Build Braun SSA (L1) after the CFG is final.
- **Flags.** Do not compute flags eagerly. Measured: 86-91% of eager x86 flag bits are never read. Fuse `Cond(cc, Flags(op,a,b))` into one compare through an exhaustively tested table.
- **Function discovery.** Seed from entry, symbols, PLT stubs, `main`, `.eh_frame` FDEs and `.pdata`. Then use recursive descent, noreturn propagation and FETCH tail-call rules. Record provenance and confidence for each start.
- **Decompiler.** Use a Phoenix-style structurer with SAILR-style deoptimizations. The goal is few gotos and high faithfulness, not zero gotos. Always fall back to correct flat output.
- **Pseudo-C view.** The statement tree is an output view of L1 only. Passes do not edit it. Each node carries an op ID, so agents can map C lines to addresses.
- **Types.** Write a hand-made C declaration parser modeled on LuaJIT `lj_cparse.c`. Layout is a function of (record, data model), with SysV, MSVC and AAPCS64 bit-field rules.
- **Demanglers.** Order: Rust v0 and legacy, then Itanium, then MSVC. Each returns a typed AST and enforces depth, node and output limits.
- **Prototypes.** Ship a tiered, embedded binary prototype database. Seed noreturn data from Ghidra's Apache-2.0 lists.
- **Quality gates.** Workspace lints, a std-only `testkit` (PRNG, property tests, shrink, fuzz), llvm-tools coverage, an STE comment lint and an optional Verus job.
- **Oracles.** Use readelf, objdump, llvm-objdump, llvm-mc, llvm-readobj, clang cross-targets, gdb, ptrace and an in-process `asm!` harness. Checked-in golden files let `cargo test` run without these tools.
- **Gap.** The research on the agent composition layer and the offline agent-quality harness was not delivered. Planning must design it from first principles (Section 3.11).

## 3. Topics

### 3.1 Ghidra architecture and program model

#### Findings

- `Program` is a facade over 15 `ProgramDB` managers with fixed indexes: `MEMORY=0 CODE=1 SYMBOL=2 NAMESPACE=3 FUNCTION=4 EXTERNAL=5 REF=6 DATA=7 EQUATE=8 BOOKMARK=9 CONTEXT=10 PROPERTY=11 TREE=12 RELOC=13 SOURCE_FILE=14`. `deleteAddressRange` and `moveAddressRange` call the managers in reverse index order. `DB_VERSION=33`. ([ProgramDB.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/database/ProgramDB.java), [Program.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/model/listing/Program.java))
- Storage is a paged B-tree database. `BufferMgr` uses 16 KiB buffers, a 4 MiB cache and copy-on-write buffer versions for physical undo (`DEFAULT_CHECKPOINT_COUNT=10`, `NUM_UNDOS=50`). After an undo, all managers drop their caches. ([DBHandle.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/DB/src/main/java/db/DBHandle.java), [BufferMgr.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/DB/src/main/java/db/buffers/BufferMgr.java), [DomainObjectAdapterDB.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/Project/src/main/java/ghidra/framework/data/DomainObjectAdapterDB.java))
- Only one DB transaction can be active. `DomainObjectDBTransaction` nests named entries. When one entry ends with `commit=false`, the whole transaction aborts. The undo name is the first non-empty description. `Command<T>` has `applyTo`, `getStatusMsg` and `getName`. ([DomainObjectDBTransaction.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/Project/src/main/java/ghidra/framework/data/DomainObjectDBTransaction.java), [Command.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/Project/src/main/java/ghidra/framework/cmd/Command.java))
- `ProgramEvent` has about 103 kinds, for example `MEMORY_BLOCK_ADDED`, `CODE_ADDED`, `SYMBOL_RENAMED`, `REFERENCE_ADDED` and `FUNCTION_BODY_CHANGED`. `ProgramChangeSet` combines address, symbol and data type change sets. ([ProgramEvent.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/util/ProgramEvent.java), [ProgramChangeSet.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/model/listing/ProgramChangeSet.java))
- An address is `(AddressSpace, offset)`. Space types: `CONSTANT=0 RAM=1 CODE=2 UNIQUE=3 REGISTER=4 STACK=5 JOIN=6 OTHER=7 SYMBOL=9 EXTERNAL=10 VARIABLE=11 DELETED=13 UNKNOWN=14 NONE=15`. CONSTANT and STACK offsets are signed. The text form is `ram:00401000`. ([AddressSpace.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/model/address/AddressSpace.java), [GenericAddress.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/model/address/GenericAddress.java))
- `AddressMapDB` packs an address into a 64-bit key: a 4-bit encoding, a 28-bit base index and a 32-bit offset. Relocatable keys (encoding 2) let `setImageBase` rebase without row rewrites. ([AddressMapDB.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/database/map/AddressMapDB.java))
- `AddressSet` is a red-black tree from range start to inclusive range end. It coalesces adjacent ranges, splits ranges on delete and supports union, intersect, subtract and xor. Function bodies, work queues and memory use it. ([AddressSet.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/model/address/AddressSet.java))
- Memory block permissions: `ARTIFICIAL=0x10 VOLATILE=0x8 READ=0x4 WRITE=0x2 EXECUTE=0x1`. Block types are DEFAULT, BIT_MAPPED and BYTE_MAPPED. An initialized block can refer to `FileBytes` (the original file, stored once). Blocks in the OTHER space are overlays and are not loaded. ([MemoryBlock.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/model/mem/MemoryBlock.java), [Memory.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/model/mem/Memory.java), [MemoryBlockType.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/model/mem/MemoryBlockType.java))
- A code unit covers each initialized address. It is an instruction, defined data or implicit 1-byte "undefined" data. Table `Instructions` stores `Proto ID` and `Flags`. Table `Data` stores a type ID. Fall-through, flow and length overrides exist. ([Listing.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/model/listing/Listing.java), [InstDBAdapter.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/database/code/InstDBAdapter.java), [DataDBAdapter.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/database/code/DataDBAdapter.java))
- Comment kinds have fixed storage ordinals: `EOL=0 PRE=1 POST=2 PLATE=3 REPEATABLE=4`. A repeatable comment shows at every location that refers to its address. ([CommentType.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/model/listing/CommentType.java), [CommentsDBAdapter.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/database/code/CommentsDBAdapter.java), [CodeUnit.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/model/listing/CodeUnit.java))
- Symbol types: `LABEL=0 LIBRARY=1 NAMESPACE=3 CLASS=4 FUNCTION=5 PARAMETER=6 LOCAL_VAR=7 GLOBAL_VAR=8`. The global namespace ID is 0. Each address has one primary symbol. Default names (`FUN_`, `LAB_`, `DAT_`, `SUB_`, `EXT_`, `UNK_`, `OFF_`, `Ordinal_`) are made on read and are not stored. ([SymbolDatabaseAdapter.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/database/symbol/SymbolDatabaseAdapter.java), [SymbolType.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/model/symbol/SymbolType.java), [SymbolTable.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/model/symbol/SymbolTable.java), [SymbolUtilities.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/model/symbol/SymbolUtilities.java))
- `SourceType` priority: DEFAULT 1, ANALYSIS 2, AI 2, IMPORTED 3, USER_DEFINED 4. `isHigherPriorityThan` decides if automation can overwrite a fact. Ghidra 12.0 (GP-6008) changed the API tests from equality to priority comparison. ([SourceType.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/model/symbol/SourceType.java), [ChangeHistory.md](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Configurations/Public_Release/src/global/docs/ChangeHistory.md))
- Reference type codes are stable bytes. Flow: `FALL_THROUGH=0 UNCONDITIONAL_JUMP=1 CONDITIONAL_JUMP=2 UNCONDITIONAL_CALL=3 CONDITIONAL_CALL=4 TERMINATOR=5 COMPUTED_JUMP=6 COMPUTED_CALL=8 INDIRECTION=9`. Data: `DATA=100 READ=101 WRITE=102 READ_WRITE=103 PARAM=107 EXTERNAL_REF=113 THUNK=127`. ([RefType.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/model/symbol/RefType.java), [ReferenceManager.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/model/symbol/ReferenceManager.java))
- References live in `FROM REFS` and `TO REFS` tables as packed `RefListV0` lists. A reference has from, to, operand index (-1 for the mnemonic), type, source and a primary flag. ([FromAdapter.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/database/references/FromAdapter.java), [RefListV0.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/database/references/RefListV0.java))
- A function is a FUNCTION symbol plus a `Function Data` row. The row holds return type, stack purge, local size, flags and calling convention. Flags are inline, noreturn, varargs, custom storage and thunk. The body is a range map to the namespace. Bodies must not overlap. ([Function.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/model/listing/Function.java), [FunctionAdapter.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/database/function/FunctionAdapter.java), [NamespaceManager.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/database/symbol/NamespaceManager.java), [StackFrame.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/model/listing/StackFrame.java), [CreateFunctionCmd.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Features/Base/src/main/java/ghidra/app/cmd/function/CreateFunctionCmd.java))
- The x86-64 gcc compiler spec gives SysV inputs RDI, RSI, RDX, RCX, R8, R9 and XMM0-7, outputs RAX/RDX and XMM0/XMM1, `extrapop=8` and `stackshift=8`. Callee-saved registers are RBX, RSP, RBP and R12-R15. ([x86-64-gcc.cspec](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Processors/x86/data/languages/x86-64-gcc.cspec), [PrototypeModel.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/model/lang/PrototypeModel.java))
- A data type ID holds its kind in the top byte (shift 56): `BUILT_IN=0 COMPOSITE=1 COMPONENT=2 ARRAY=3 POINTER=4 TYPEDEF=5 FUNCTION_DEF=6 PARAMETER=7 ENUM=8 BITFIELD=9`. Types live in a category tree. `resolve` removes duplicate types and applies a conflict policy. ([DataTypeManagerDB.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/database/data/DataTypeManagerDB.java), [DataTypeManager.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/model/data/DataTypeManager.java))
- Bookmarks allow one entry per (address, type, category). The types are Note, Info, Error, Warning and Analysis. ([BookmarkManager.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/model/listing/BookmarkManager.java), [BookmarkType.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/model/listing/BookmarkType.java))

Bands: `FORMAT=100 BLOCK=200 DISASSEMBLY=300 CODE=400 FUNCTION=500 REFERENCE=600 DATA=700 FUNCTION_ID=800 DATA_TYPE_PROPOGATION=900`. ([Analyzer.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Features/Base/src/main/java/ghidra/app/services/Analyzer.java), [AnalyzerType.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Features/Base/src/main/java/ghidra/app/services/AnalyzerType.java), [AnalysisPriority.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Features/Base/src/main/java/ghidra/app/services/AnalysisPriority.java))
- Real priorities: `Entry Points=200 Non-Returning Discovered=302 Function Start Search=402 Constant Reference=596 Reference=600 Data Reference=602 demanglers=897 Parameter ID=902 Stack=903 ASCII Strings=905`. ([EntryPointAnalyzer.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Features/Base/src/main/java/ghidra/app/plugin/core/disassembler/EntryPointAnalyzer.java), [OperandReferenceAnalyzer.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Features/Base/src/main/java/ghidra/app/plugin/core/analysis/OperandReferenceAnalyzer.java), [StackVariableAnalyzer.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Features/Base/src/main/java/ghidra/app/plugin/core/function/StackVariableAnalyzer.java), [StringsAnalyzer.java](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Features/Base/src/main/java/ghidra/app/plugin/core/string/StringsAnalyzer.java))

#### Design implications

- Modules: `addr`, `mem`, `listing`, `symbols`, `refs`, `funcs`, `types`, `marks`, `tx`, `analysis`, `api`, `json`, `cli`, `rpc`. One `Program` owns all managers.
- Keep: the address model, AddressSet algebra, block permission bits, code units, 5 comment kinds and the namespace tree. Also keep RefType numbering, the function model, kind-tagged type IDs, bookmarks, the analyzer contract and scheduler, equates, relocations and register context.
- Simplify: in-memory `BTreeMap` tables, one versioned snapshot format with migration functions, logical undo, one generic per-address key-value property store and hard-coded calling-convention tables (no XML).
- Drop from the MVP: program trees, the source-file manager, the paged B-tree, `.gdt` archive sync, bit-mapped blocks, JOIN/UNIQUE/VARIABLE/HASH spaces, Ghidra Server and JVM scripts.
- Core shapes: `Address{space: SpaceId(u16), off: u64}` ordered by (space, off); `AddressSet = BTreeMap<Address, Address>`; `CodeUnit::{Insn{len, flow}, Data{type_id, len}}`; `Ref{from, to, op_index: i8, kind: u8, source, primary}`; `Tx{id, label, depth, poisoned}`.
- Memory: `Block{name, start, len, perms, kind: Init{file_off}|Uninit|ByteMapped{target}, overlay, source}`. Store the original file once plus a sparse patch map. Answer "file offset of VA", "original or patched byte" and "write patched file".
- A `Module` trait gives `delete_range` and `move_range`. The cascade order is explicit and tested. A rebase is one `move_range` cascade in one transaction with one coalesced event.
- One event bus `{kind, AddressSet or object ID, tx, rev}` feeds the analysis scheduler and the agent query "what changed since revision N".
- Every setter compares SourceType priority. A blocked write returns `BLOCKED_BY_HIGHER_PRIORITY_SOURCE` with the current value and source.
- Default names are computed on read. The name resolver accepts them as lookup keys.
- Bookmarks are the agent work queue and findings log, with types TODO, Hypothesis, Finding and Error.
- Analysis tools: `analysis_status` and `analysis_run{until_priority, max_steps}`. The queue is `BinaryHeap<Reverse<(prio, idx)>>`.
- Post-MVP: BSim-like similarity (WL hashes, IDF-weighted cosine, banded LSH) and VT-like matching (exact bytes, masked instructions, mnemonics, implied propagation).
- Tests: AddressSet property tests against a `Vec<bool>` model. Random command sequences, then undo all and compare a canonical state hash. Snapshot round trip byte for byte. Scheduler order and determinism. SourceType guard tests.

#### Pitfalls

- A delete or move cascade that misses one manager leaves dangling references. Ghidra calls the managers in reverse index order.
- An inverse operation must capture all implicit side effects. Example: a clear of code units also removes the references from those units.
- Compare SourceType priority, not equality. AI and ANALYSIS share priority 2 in Ghidra, so set the AGENT rank explicitly.
- Never change persisted enum numbers (comment kinds, reference kinds, permission bits).
- Analyzers that create code start other analyzers. Use a work budget and a fixpoint test. Do not recurse.
- An overlapping function body is an error. The error must name the owner function. Shared tails need a policy.
- STACK and CONSTANT offsets are signed. Use an `i64` view, or negative stack offsets print incorrectly.
- Bulk analysis can emit very many events. Coalesce the events of one transaction into AddressSets.
- Overlay spaces make reference resolution difficult. Defer overlays, or define the rule early.
- A persisted default name becomes stale after a rename or a move.

### 3.2 Agentic RE tool landscape

#### Findings

- GhidraMCP has about 29 address-centric tools, for example `list_functions(offset, limit=100, filter)`, `list_strings(limit=200)`, `disassemble_function(limit=500)` and `read_memory` (max 4096 bytes). It tells the agent to call `get_program_info` first and to prefer address tools. ([GhidraMCP](https://github.com/LaurieWired/GhidraMCP))
- The GhidraMCP backend uses `{success, data}` or `{success:false, error:{code, message}}`. A page is `{items, offset, limit, total, has_more}` with a max limit of 2000. Codes include `BAD_ADDRESS`, `FUNCTION_NOT_FOUND`, `AMBIGUOUS_NAME`, `NAME_CONFLICT`, `DECOMPILE_FAILED` and `NOT_READY`. `AMBIGUOUS_NAME` lists each `name @ addr` candidate. ([GhidraMCP](https://github.com/LaurieWired/GhidraMCP))
- ReVa has about 95 small tools that accept varied input. `get-decompilation` returns 50 lines by default. Results report `resolvedFrom`, capped lists with totals and per-section errors. An unknown program gives "Did you mean" suggestions. ([ReVa](https://github.com/cyberkaida/reverse-engineering-assistant))
- The ReVa triage order: program, memory blocks, string count then pages, imports by category, function counts, xrefs to items of interest, then a short decompile. ([ReVa](https://github.com/cyberkaida/reverse-engineering-assistant))
- ida-pro-mcp is batch-first. A tool takes one item or a list and returns an error per item. Cursor pages default to 1000 items (max 10000). Output above 50000 characters becomes a preview. `survey_binary` is the documented first call. ([ida-pro-mcp](https://github.com/mrexodia/ida-pro-mcp))
- ida-pro-mcp also has `analyze_function` (pseudocode capped at 100 lines, strings, constants, callers, callees, complexity) and `int_convert`, because LLMs must not convert number bases. Tool profiles make the tool set smaller. ([ida-pro-mcp](https://github.com/mrexodia/ida-pro-mcp))
- The official Hex-Rays IDA MCP uses code mode with six tools, one of them `execute_python`. Hex-Rays reports about 20% fewer tokens than per-feature servers. It logs each call to JSONL and never retries a failed mutating call. ([HexRaysSA ida-mcp](https://github.com/HexRaysSA/ida-mcp), [Hex-Rays blog](https://hex-rays.com/blog/hex-rays-ida-mcp-server))
- GhidrAssistMCP v3 replaced 49 selector-style tools with 100 explicit tools. Names: `get_*` for one object, `list_*` for collections, `search_*` for filtered discovery, a verb for mutations. It adds async jobs and a hash of each function body. ([GhidrAssistMCP](https://github.com/jtang613/GhidrAssistMCP))
- pyghidra-mcp keeps about 20 tools. Every call names `binary_name`. A timeout on one item is an item error, not a failed call. Analysis readiness and index readiness are separate states. ([pyghidra-mcp](https://github.com/clearbluejar/pyghidra-mcp))
- radare2-mcp puts usage hints in tool descriptions, has a `calculate` tool and offers mini, read-only and sandbox modes. List tools take `filter`, `count=true` and cursor pages. ([radare2-mcp](https://github.com/radareorg/radare2-mcp))
- Binary Ninja MCP reads an address input as an expression (`0x401000`, `main`, `.text`). Decimal input needs the `0n` prefix. Output addresses are hex strings. Handles are opaque and scoped to the session. ([Binary Ninja MCP docs](https://dev-docs.binary.ninja/guide/mcp.html), [binary_ninja_mcp](https://github.com/fosdickio/binary_ninja_mcp))
- The angr-management MCP server logs each call with its arguments, result and duration in a history view. ([angr-management MCP](https://docs.angr.io/projects/angr-management/en/latest/mcp_server.html))
- Common problems: client timeouts too short for decompilation, GUI-thread deadlocks, option mismatches, a stale active program and arguments sent as JSON-encoded strings. One client refused more than 100 tools. ([GhidraMCP issues](https://github.com/LaurieWired/GhidraMCP/issues), [ida-pro-mcp #226](https://github.com/mrexodia/ida-pro-mcp/issues/226), [HN discussion](https://news.ycombinator.com/item?id=46882389))
- Anthropic guidance: build fewer, consolidated tools with namespaces, and return high-signal fields. Offer concise and detailed formats (72 vs 206 tokens in one example). Make errors actionable. Claude Code caps a tool result at 25,000 tokens by default. ([Writing tools for agents](https://www.anthropic.com/engineering/writing-tools-for-agents))
- Context guidance: code execution cut one example from 150,000 to 2,000 tokens. Use progressive disclosure, lightweight references first and notes outside the context. ([Code execution with MCP](https://www.anthropic.com/engineering/code-execution-with-mcp), [Context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents))
- Tool search cut upfront context from about 77K to 8.7K tokens. It raised accuracy, for example Opus 4.5 from 79.5% to 88.1%. Input examples raised accuracy on complex parameters from 72% to 90%. ([Advanced tool use](https://www.anthropic.com/engineering/advanced-tool-use))
- Decompiler output is not ground truth. Raw Ghidra output passes re-execution for about 20% of functions. LLM decompilers read better but have 52.2% lower functional correctness. ([LLM4Decompile](https://arxiv.org/abs/2403.05286), [DecompileBench](https://arxiv.org/abs/2505.11340), [DecLLM](https://conf.researchr.org/details/issta-2025/issta-2025-papers/80/DecLLM-LLM-Augmented-Recompilable-Decompilation-for-Enabling-Programmatic-Use-of-Dec), [Idioms](https://arxiv.org/abs/2502.04536))
- Structured facts help symbol recovery. ReSym combines variable and field-access models through Prolog facts. It reaches 56.4% on names, 64.6% on types and 72.9% on struct layout. GenNm uses caller and callee names as context. ([ReSym](https://www.cs.purdue.edu/homes/lintan/publications/resym-ccs24.pdf), [GenNm](https://arxiv.org/abs/2306.02546))
- A GhidraMCP case study: in large binaries the agent analyzed only 10-15% of functions in depth. It renamed inconsistently and lost context. A progress metric and a feedback loop improved results. ([GhidraMCP QRS study](https://arxiv.org/html/2606.06838))

#### Design implications

- Use one registry for CLI and MCP: the same names, schemas and output.
- Every result uses one envelope: `ok`, `data`, `page{offset, limit, total, next}`, `truncated`, `hints[]` and `error{code, message, hint, candidates}`.
- An ambiguous name is an error with candidates. Never use the first match silently.
- Add composite tools (`binary_survey`, a function context bundle) to reduce round trips. A batch input returns an error per item.
- Disassembly and pseudocode lines carry address markers. A calc tool converts number bases and does address arithmetic.
- Coerce JSON-encoded string arguments and report the coercion as a warning.
- A mutation returns the new revision. A read-only mode exists.
- Report coverage (functions analyzed, named, typed) and keep a notes store. Agents then keep state across context resets.
- Mark text from the binary as data. Escape control characters and cap the length.
- MVP tools: info, survey, functions, function context, disasm, xrefs, strings, search, bytes, calc, rename, comment and notes.

#### Pitfalls

- Do not expose many overlapping tools. Give a way to make the tool set smaller.
- Do not send unbounded output. Do not truncate without a cursor and a hint.
- Do not resolve a name to the first match without a message.
- Do not send addresses as JSON numbers. Values above 2^53 lose precision.
- Do not depend on implicit active-target state or on GUI-only features.
- Do not fail a whole call when one item fails or times out.
- Do not return exception text. Return an error code and a hint.
- Do not write logs to stdout in stdio mode.

### 3.3 Executable formats (ELF, PE/COFF, Mach-O)

#### Findings

- A bounded read is `data.get(off..)?.get(..len)`. It never computes `off + len`, so it cannot overflow. Counts use `checked_mul`. ULEB128 rejects a 10th byte other than 0x00/0x01 (SLEB128: 0x00/0x7f). Read fields with `u32::from_le_bytes`, not pointer casts. ([object read_ref.rs](https://github.com/gimli-rs/object/blob/master/src/read/read_ref.rs), [object util.rs](https://github.com/gimli-rs/object/blob/master/src/read/util.rs), [object pod.rs](https://github.com/gimli-rs/object/blob/master/src/pod.rs))
- The `object` crate is for trusted input only. It does not copy platform loaders. ghidorah takes hostile binaries, so it needs resource caps, loader-faithful mapping and recovery after errors. ([object README](https://github.com/gimli-rs/object))
- goblin fuzz bugs give the classes to design against. Two are OOM from `Vec::with_capacity(untrusted_count)` (#120) and an infinite note loop after a parse error (#108). Others are cyclic PE resource trees, add/sub overflow panics and OOB reads in unwind and certificate parsers. The fix for #120 clamps each count to `file_len / entry_size`. ([goblin CHANGELOG](https://github.com/m4b/goblin/blob/HEAD/CHANGELOG.md), [goblin #120](https://github.com/m4b/goblin/issues/120), [goblin #108](https://github.com/m4b/goblin/issues/108))
- An iterator that returns `Err` before it advances loops forever when the caller continues. Rule: every table iterator stops after its first error. An ELF note header is always 12 bytes. Note alignment is 4 or 8 from `p_align` or `sh_addralign`. ([object note.rs](https://github.com/gimli-rs/object/blob/master/src/read/elf/note.rs), [gABI program header](https://refspecs.linuxfoundation.org/elf/gabi4+/ch5.pheader.html))
- ELF escape values: `e_phnum==0xffff` puts the real count in `section0.sh_info`. `e_shnum==0` with `e_shoff!=0` puts it in `section0.sh_size`. `e_shstrndx==0xffff` puts it in `section0.sh_link`. `st_shndx==SHN_XINDEX` reads `SHT_SYMTAB_SHNDX`. ([object elf/file.rs](https://github.com/gimli-rs/object/blob/master/src/read/elf/file.rs), [object elf.rs](https://github.com/gimli-rs/object/blob/master/src/elf.rs))
- `r_info` split: ELF32 `sym=info>>8, type=info&0xff`; ELF64 `sym=info>>32, type=info&0xffffffff`. MIPS64 little-endian uses a different byte layout. ([object elf.rs](https://github.com/gimli-rs/object/blob/master/src/elf.rs), [glibc elf.h](https://sourceware.org/git/?p=glibc.git;a=blob;f=elf/elf.h))
- Measured: a gcc PIE with zero `e_shoff`, `e_shnum` and `e_shstrndx` still runs. objdump then prints nothing, but `readelf -D -r` still shows the relocations. The loader must build its view from `PT_LOAD` and `PT_DYNAMIC`. ([Oracle fake section headers](https://blogs.oracle.com/solaris/what-are-fake-elf-section-headers), [dustri](https://dustri.org/b/screwing-elf-header-for-fun-and-profit.html))
- Without section headers, use `DT_SYMTAB`, `DT_STRTAB/STRSZ`, `DT_RELA/RELASZ/RELAENT`, `DT_JMPREL/PLTRELSZ/PLTREL` (7=RELA, 17=REL), `DT_RELR/RELRSZ`, `DT_PLTGOT`, `DT_NEEDED`, `DT_SONAME` and `DT_INIT_ARRAY`. Map a VA through the `PT_LOAD` that contains it. Bytes in `[filesz, memsz)` read as zero. ([gABI program header](https://refspecs.linuxfoundation.org/elf/gabi4+/ch5.pheader.html))
- Dynamic symbol count: with `DT_HASH`, `nchain` is the count. With only `DT_GNU_HASH`, take the largest bucket value and walk the chain until an entry has bit 0 set. The count is that index + 1. Limit each walk to the table length. ([object hash.rs](https://github.com/gimli-rs/object/blob/master/src/read/elf/hash.rs))
- Measured x86-64 PLT forms (gcc 13.3, IBT on): `.plt` has PLT0, then 16-byte lazy stubs (`f3 0f 1e fa`, `68 imm32`, `e9 rel32`). `.plt.sec` entries are `f3 0f 1e fa ff 25 disp32` plus a 6-byte NOP. `.plt.got` serves GLOB_DAT-only imports. `-fno-plt` call sites use `ff 15 disp32`. ([binutils ibt-plt-1.d](https://gnu.googlesource.com/binutils-gdb/+/63f0e930d4667eb7dbc95c78f770cd58acd328ef/ld/testsuite/ld-x86-64/ibt-plt-1.d), [perf .plt.sec](https://lkml.rescloud.iu.edu/2301.3/09042.html))
- Stub matcher: skip an optional `f3 0f 1e fa` and an optional `f2`, then expect `ff 25`. The slot is next_ip + disp32. Name the stub through the JUMP_SLOT or GLOB_DAT relocation whose `r_offset` equals the slot, not by position. IFUNC binaries reorder `.got.plt` relocations. ([binutils synthetic symtab](https://www.sourceware.org/ml/binutils/2017-08/msg00348.html), [bug 17677](https://sourceware.org/bugzilla/show_bug.cgi?id=17677))
- CVE-2017-14729 was a heap overflow because the PLT code did not keep one entry per symbol. Use a map from slot address to relocation and make sure each name is unique. `-z mark-plt` adds `DT_X86_64_PLT`, `PLTSZ` and `PLTENT` as hints. ([CVE-2017-14729](https://tenable.com/cve/CVE-2017-14729), [mark-plt commit](https://gnu.googlesource.com/binutils-gdb/+/832ca732b8a96ff9a3e7c4abf24098bf2a59a96d))
- Other stubs: i386 PIC uses `ff a3 disp32` with EBX = `DT_PLTGOT`, and its lazy push operand is a byte offset, not an index. AArch64 uses `adrp x16; ldr x17; add x16; br x17`. Mach-O x86_64 `__stubs` is `ff 25 disp32` (6 bytes). Mach-O arm64 is `adrp; ldr; br` (12 bytes). ([xnu loader.h](https://raw.githubusercontent.com/apple-oss-distributions/xnu/main/EXTERNAL_HEADERS/mach-o/loader.h))
- ELF relocation constants: `R_X86_64_64=1 PC32=2 COPY=5 GLOB_DAT=6 JUMP_SLOT=7 RELATIVE=8 DTPMOD64=16 TPOFF64=18 IRELATIVE=37`; `R_386_GLOB_DAT=6 JMP_SLOT=7 RELATIVE=8`; `R_AARCH64_GLOB_DAT=1025 JUMP_SLOT=1026 RELATIVE=1027`; `DT_RELR=36 DT_RELRSZ=35 SHT_RELR=19`. ([glibc elf.h](https://sourceware.org/git/?p=glibc.git;a=blob;f=elf/elf.h))
- RELR: an even entry is an address to relocate. An odd entry is a bitmap of 63 words (31 on ELF32). All entries are implicit RELATIVE relocations. Build-id is note type `NT_GNU_BUILD_ID=3` with name `GNU`. `GNU_PROPERTY_X86_FEATURE_1_AND=0xc0000002` bit 0 (IBT) tells that `.plt.sec` exists. ([SHT_RELR proposal](https://groups.google.com/g/generic-abi/c/bX460iggiKg/m/0PMCJ0hjBAAJ), [glibc elf.h](https://sourceware.org/git/?p=glibc.git;a=blob;f=elf/elf.h))
- PE headers: `e_lfanew` is at 0x3C. The signature is `PE\0\0`. The COFF header is 20 bytes. Machines: `0x14c` i386, `0x8664` AMD64, `0xaa64` ARM64. Optional header magic is `0x10b` (PE32) or `0x20b` (PE32+). Data directories start at +96 or +112. Section headers are 40 bytes. ([PE format](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format))
- PE directory indexes: `0 Export, 1 Import, 2 Resource, 3 Exception, 4 Certificate, 5 BaseReloc, 6 Debug, 9 TLS, 10 LoadConfig, 11 BoundImport, 12 IAT, 13 DelayImport, 14 CLR`. Directory 4 holds a file offset, not an RVA. ([PE format](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format))
- PE imports: a descriptor is 20 bytes, and the table ends at an all-zero entry. ILT and IAT entries are 4 or 8 bytes. The top bit selects import by ordinal. The loader ignores the directory size. A null ILT means "use the IAT". A pre-bound IAT holds VAs, so read names from the ILT. ([PE format](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format), [corkami PE](https://github.com/corkami/docs/blob/master/PE/PE.md))
- PE delay imports: the descriptor is 32 bytes. Attributes bit 0 set means RVAs. Bit 0 clear (VC6) means VAs. Measured: lld-link gives `Attributes=0x1`. Corrupt delay data does not stop execution, so it is a diagnostic, not a fatal error. ([PE format](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format), [corkami PE](https://github.com/corkami/docs/blob/master/PE/PE.md))
- PE exports: the directory is 40 bytes. Name-ordinal entries are unbiased indexes, and ordinal = index + Base. An EAT RVA inside the export directory is a forwarder string (`DLL.func` or `DLL.#27`). Clamp `NumberOfFunctions` and `NumberOfNames` by the bytes left. ([object pe/export.rs](https://github.com/gimli-rs/object/blob/master/src/read/pe/export.rs), [corkami PE](https://github.com/corkami/docs/blob/master/PE/PE.md))
- PE base relocations: a block is PageRVA + BlockSize (with the 8-byte header), then u16 entries (type in the high 4 bits: ABSOLUTE=0, HIGHLOW=3, DIR64=10). A BlockSize below 8 loops forever. TLS callback addresses are VAs. Callbacks run before the entry point, so cap them (for example at 256). ([PE format](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format), [corkami PE](https://github.com/corkami/docs/blob/master/PE/PE.md))
- x64 `.pdata`: `RUNTIME_FUNCTION` is 12 bytes (Begin, End and UnwindInfo RVAs), sorted. `UNWIND_INFO` flags are EHANDLER=1, UHANDLER=2 and CHAININFO=4. Cap the chain depth (32) and keep a visited set. `.pdata` gives reliable function starts. ([x64 exception handling](https://learn.microsoft.com/en-us/cpp/build/exception-handling-x64))
- Map RVAs as the Windows loader does. VirtualSize 0 means SizeOfRawData. PointerToRawData below 0x200 rounds down to 0. Sections can overlap or extend past EOF. RVAs below SizeOfHeaders map to the same file offset. NumberOfRvaAndSizes above 16 counts as 16. ([object pe/section.rs](https://github.com/gimli-rs/object/blob/master/src/read/pe/section.rs), [corkami PE](https://github.com/corkami/docs/blob/master/PE/PE.md))
- Mach-O: `MH_MAGIC_64=0xfeedfacf`. The header is 32 bytes. `cmdsize` must be a multiple of 8 (64-bit). Commands: `LC_SEGMENT_64=0x19 LC_SYMTAB=0x2 LC_DYSYMTAB=0xb LC_LOAD_DYLIB=0xc LC_UUID=0x1b LC_FUNCTION_STARTS=0x26 LC_DYLD_INFO_ONLY=0x80000022 LC_MAIN=0x80000028 LC_DYLD_CHAINED_FIXUPS=0x80000034`. `LC_MAIN.entryoff` is a file offset. ([xnu loader.h](https://raw.githubusercontent.com/apple-oss-distributions/xnu/main/EXTERNAL_HEADERS/mach-o/loader.h))
- Mach-O stubs resolve without fixup decode. For `S_SYMBOL_STUBS=0x8`, `reserved1` is the first indirect-table index and `reserved2` is the stub size. Pointer sections (types 0x6 and 0x7) map entry i to `indirect[reserved1+i]`. `INDIRECT_SYMBOL_LOCAL=0x80000000` and `INDIRECT_SYMBOL_ABS=0x40000000` have no name. ([xnu loader.h](https://raw.githubusercontent.com/apple-oss-distributions/xnu/main/EXTERNAL_HEADERS/mach-o/loader.h))
- Chained fixups: the header has 7 u32 fields. `page_start 0xFFFF` means no fixups. `DYLD_CHAINED_PTR_64=2` and `PTR_64_OFFSET=6` use a 4-byte stride. ARM64E and USERLAND use 8. Keep each `next` walk inside its page and bound `imports_count` by the data. ([xnu fixup-chains.h](https://raw.githubusercontent.com/apple-oss-distributions/xnu/main/EXTERNAL_HEADERS/mach-o/fixup-chains.h))
- `LC_DYLD_INFO` streams use opcode `byte & 0xF0` and immediate `byte & 0x0F`. A "times" ULEB can ask for 2^64 iterations, so charge a work budget. Export tries can loop, so keep a visited set and a depth cap. ([xnu loader.h](https://raw.githubusercontent.com/apple-oss-distributions/xnu/main/EXTERNAL_HEADERS/mach-o/loader.h), [LLVM macho-bad-trie](https://llvm.googlesource.com/llvm/+/refs/heads/master/test/tools/llvm-objdump/macho-bad-trie.test), [LLVM bug 32405](https://lists.llvm.org/pipermail/llvm-bugs/2017-March/054461.html))
- Mach-O robustness: `cmdsize < 8` loops forever. Read `ncmds` only inside `sizeofcmds`. YARA CVE-2019-19648 came from an unchecked `cmdsize`. Fat headers are big-endian. `0xcafebabe` can also start a Java class file: a u32 at offset 4 below 20 means fat. ([object load_command.rs](https://github.com/gimli-rs/object/blob/master/src/read/macho/load_command.rs), [CVE-2019-19648](https://nvd.nist.gov/vuln/detail/CVE-2019-19648), [file magic cafebabe](https://cgit.freebsd.org/src/tree/contrib/file/magic/Magdir/cafebabe))
- Identity: ELF `NT_GNU_BUILD_ID`, Mach-O `LC_UUID` and PE CodeView `RSDS` (GUID, age, PDB path) normalize to one record. Add SHA-256 of the whole file (about 150 lines with std). ([object traits.rs](https://github.com/gimli-rs/object/blob/master/src/read/traits.rs), [PE format](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format))
- `object` puts per-format raw parsers under one generic trait and detects the format from 16 magic bytes. The generic lifetimes make serialization hard. An owned model fits a JSON API better. ([object traits.rs](https://github.com/gimli-rs/object/blob/master/src/read/traits.rs), [object mod.rs](https://github.com/gimli-rs/object/blob/master/src/read/mod.rs))
- Ghidra turns PLT entries into thunks to external functions and marks GOT entries as constant pointers. ([ElfDefaultGotPltMarkup](https://ghidra.re/ghidra_docs/api/ghidra/app/util/bin/format/elf/ElfDefaultGotPltMarkup.html))
- Measured: the host makes all fixtures offline. gcc makes PIE variants. clang + ld.lld make ppc64 BE, mips BE, i386, armv7, aarch64 and riscv64. lld-link makes PE32+ (imports, delay loads, forwarders, TLS, DIR64, `.pdata`). ld64.lld makes Mach-O. `llvm-lipo` is not installed.

#### Design implications

- Use two layers. Layer (a) is lazy per-format parsers over `&[u8]`, one function per table, each with a `Result` and diagnostics. Layer (b) is an owned `Binary` model that agents and analysis use.
- `Binary` fields: `format arch bits endian kind image_base entry_points segments sections symbols imports exports relocs import_slots stubs libraries identity diagnostics`. Entry point kinds are entry, main, tls_callback, init_array and export.
- `Reader<'a>{data, base, endian}` gives u8..u64, uword, bytes, sub, cstr(off, max_len), uleb128, sleb128 and align_to. All arithmetic uses `checked_*`. Parser crates use `#![forbid(unsafe_code)]`.
- `ParseError{code, path, offset, need, have, hint}` uses codes `E_OOB E_OVERFLOW E_BAD_MAGIC E_LIMIT E_LOOP E_BAD_ALIGN` and paths such as `pe.import[3].ilt[17]`. Only an unknown magic or a truncated main header is fatal.
- `Limits` defaults: `file=1GiB sections=65535 symbols=4M relocs=16M load_cmds=65536 imports_per_dll=65536 dlls=4096 tls_callbacks=256 unwind_depth=32 string=4096B bind_steps=64M trie_depth=128`. Clamp each count to remaining bytes / entry size before allocation.
- No loop advances by a file value until the value is proved to be greater than zero (reloc BlockSize, `cmdsize`, note size, ULEB times).
- One `MemoryMap` of regions `{va, vsize, file_off, file_size, perms, name, source}` serves all formats. `read(va, len)` fills the bss tail with zeros. Every parser that reads by address uses it.
- Import resolution has two parts. A format gives import slots (ELF JUMP_SLOT/GLOB_DAT, PE IAT, Mach-O pointers). An ISA gives a stub matcher. One generic pass names `name@plt`, `name@stub` or `dll!name`, also without section headers.
- Stable IDs: `imp:<lib>!<name>`, `imp:<lib>!#<ord>`, `exp:<name>`, `sym:<addr>:<name>`, `sec:<index>:<name>`, `seg:<index>`. Sort by address or index, never by hash order.
- Each format has `probe(&[u8]) -> Option<(Format, confidence, reason)>`. MZ without a PE signature is `dos_mz`. A probe never panics on short input.
- MVP for ELF: ELF32/64 LE and BE with escapes, dynamic section, REL/RELA/RELR, notes, segment-only fallback and PLT naming. MVP for PE: PE32/PE32+ with imports, delay imports, exports, base relocs, TLS and `.pdata`. MVP for Mach-O: 32/64 and fat with stubs, `LC_MAIN`, `LC_UUID`, function starts and chained fixups.
- Defer: PE resources, certificates, load config, ARM64 `.pdata`, the Mach-O export trie, ELF symbol versions (show `@VERSION` only), DWARF and archives.
- Tests: in-repo byte builders (ElfBuilder, PeBuilder, MachOBuilder, FatBuilder) make minimal valid files. Each finding gets one malformed variant: huge counts, offsets past EOF, zero-advance tables, cycles and unterminated tables.
- Tests: a never-panic mutation harness runs `load()` under `catch_unwind` with a fixed seed (about 10k cases per seed). Differential tests compare with `readelf -W`, `llvm-readobj --coff-*` and `llvm-objdump --macho`. A stripped-header test zeroes `e_shoff` on a gcc PIE.

#### Pitfalls

- Do not compute `offset + size` before the bounds test. Do not call `Vec::with_capacity` with a file count before you clamp it.
- `e_phentsize` and `e_shentsize` must be at least the struct size. Step by entsize. Do not divide by `sh_entsize==0`. `SHT_NOBITS` has no file bytes.
- `DT_PLTREL` decides if JMPREL entries are REL or RELA. `.plt.sec` has no PLT0 header.
- GLOB_DAT-only imports and `-fno-plt` builds have no `.plt.sec` entry. Name the GOT slot itself, or call sites show bare addresses.
- PE: the ordinal flag is bit 31 (PE32) or bit 63 (PE32+). TLS callbacks and old delay-import fields are VAs. `SizeOfOptionalHeader` is the distance to the section table, not the header size.
- Strict mapping in the style of `object` gives wrong or missing data on malware. Use the loader rules.
- Mach-O: the stub size comes from `reserved2` (6, 12 or 16). `PTR_64` rebase targets are VAs, but `PTR_64_OFFSET` targets are offsets from `__TEXT`. Shift `high8` into bits 56-63.
- MinGW PE files often keep a COFF symbol table. Long section names such as `/4` point into its string table.
- Use `overflow-checks = true` in the release profile of parser crates. Wrap each file load in `catch_unwind` at the server boundary, so one bad sample does not stop the session.
- Endian errors hide in `r_info`, hash tables and notes. Use ELF64 BE and ELF32 BE fixtures.

### 3.4 Instruction decoders (x86-64, AArch64, RV64IC)

#### Findings

- x86 layout: legacy prefixes, REX/VEX/EVEX/REX2, opcode (1-3 bytes), ModRM, SIB, displacement (0/1/2/4/8), immediate (0/1/2/4/8). The max length is 15 bytes. Prefix groups: G1 `F0 F2 F3`, G2 `2E 36 3E 26 64 65`, G3 `66`, G4 `67`. In 64-bit mode only FS and GS change the address. `3E` is NOTRACK on indirect JMP/CALL. ([iced decoder.rs](https://github.com/icedland/iced/blob/master/src/rust/iced-x86/src/decoder.rs), [mishegos](https://blog.trailofbits.com/2019/10/31/destroying-x86_64-instruction-decoders-with-differential-fuzzing/))
- Measured (objdump 2.42, llvm-mc 18): when F2 and F3 both occur, the last one wins. F2/F3 has precedence over 66 as the mandatory prefix (`66 f2 0f 58 c1` is addsd).
- REX is `0100WRXB` and is valid only directly before the opcode. A REX before a legacy prefix is ignored, and the oracles differ (objdump `rex.W`, LLVM `data16`). Any REX, also `40`, maps byte registers 4-7 to SPL/BPL/SIL/DIL. `41 90` is `xchg r8d,eax`. `f3 90` is PAUSE. ([felixcloutier PUSH](https://www.felixcloutier.com/x86/push))
- ModRM/SIB in 64-bit mode: rm=100 needs a SIB, so `[r12]` is `41 8b 04 24`. mod=00 rm=101 is RIP+disp32, so `[r13]` needs disp8=0. SIB index=100 with REX.X=0 means no index. SIB base=101 with mod=00 means disp32 and no base. The RIP base is the next instruction address. Measured: 2.7% of instructions are RIP-relative.
- Operand size: default 32, REX.W gives 64, else 66 gives 16. Immediates are at most 32 bits, sign-extended to 64. Exceptions: `B8+r` with REX.W takes imm64, and `A0-A3` take an 8-byte address. `83`, `6B` and `6A` take a sign-extended imm8. A write to a 32-bit register zero-extends to 64 bits. ([InstructionDefs.txt](https://raw.githubusercontent.com/icedland/iced/master/src/csharp/Intel/Generator/Tables/InstructionDefs.txt))
- Default 64-bit operand size (`do64`): `50+r 58+r 68 6A 8F/0 9C 9D C2 C3 C8 C9 E0-E3 E8 E9 EB 70-7F 0F80-8F FF/2 FF/4 FF/6`. Intel ignores 66 on near branches, AMD applies it. objdump uses the AMD rule, LLVM the Intel rule. iced has `DecoderOptions::AMD`. ([InstructionDefs.txt](https://raw.githubusercontent.com/icedland/iced/master/src/csharp/Intel/Generator/Tables/InstructionDefs.txt), [iced-x86](https://github.com/icedland/iced/tree/master/src/rust/iced-x86))
- Invalid or reused in 64-bit mode: `06 07 0E 16 17 1E 1F 27 2F 37 3F 60 61 82 9A CE D4 D6 EA`. `40-4F` are REX, `62` is EVEX, `63` is MOVSXD, `C4/C5` are VEX, and `D5` is the APX REX2 prefix. ([InstructionDefs.txt](https://raw.githubusercontent.com/icedland/iced/master/src/csharp/Intel/Generator/Tables/InstructionDefs.txt))
- VEX3 is `C4 [R̄X̄B̄ m4..m0] [W v̄3..v̄0 L pp]`. VEX2 is `C5 [R̄ v̄3..v̄0 L pp]` (map 0F, W=0). pp 0-3 means none/66/F3/F2. EVEX is `62 P0 P1 P2` with z, L'L, b, V̄' and aaa. disp8*N needs a tuple type per instruction. REX2 is `D5 [M0 R4 X4 B4 W R3 X3 B3]`. ([VEX prefix](https://en.wikipedia.org/wiki/VEX_prefix), [EVEX prefix](https://en.wikipedia.org/wiki/EVEX_prefix), [binutils APX patch](https://patchwork.sourceware.org/project/binutils/patch/20230919152527.497773-2-lili.cui@intel.com/), [Linux REX2 patch](https://lkml.iu.edu/hypermail/linux/kernel/2405.0/01472.html))
- Measured: both oracles accept 66/F2/F3/REX/LOCK before VEX, but hardware raises #UD. A strict decoder therefore differs from both oracles.
- Opcode maps are 1-byte, 0F, 0F38 (no immediate) and 0F3A (always imm8). In map 0F, NP/66/F3/F2 choose the SSE column. ModRM.reg selects the instruction in groups 80-83, C0/C1/D0-D3, F6/F7, FE/FF and 0F 00/01/BA/C7/AE. Length depends only on prefixes, map, opcode, ModRM/SIB displacement and immediate size.
- iced-x86 generates tables with a C# generator from text records such as `INSTRUCTION: o64 01 /r | ADD r/m64, r64 | X64`. Its `Instruction` is 40 bytes. `FlowControl` has Next, UnconditionalBranch, IndirectBranch, ConditionalBranch, Return, Call, IndirectCall, Interrupt and Exception. Errors are NoMoreBytes and InvalidInstruction. ([iced tables](https://github.com/icedland/iced/tree/master/src/csharp/Intel/Generator/Tables), [instruction.rs](https://github.com/icedland/iced/blob/master/src/rust/iced-x86/src/instruction.rs), [enums.rs](https://github.com/icedland/iced/blob/master/src/rust/iced-x86/src/enums.rs))
- iced tests: `DecoderTest64.txt` has 43,618 lines such as `hex, Code, Mnemonic, opcount, op0=r;rcx ...`. iced is compared with xed, gas, objdump, masm, dumpbin, nasm and ndisasm, and is fuzzed. ([DecoderTest64.txt](https://raw.githubusercontent.com/icedland/iced/master/src/UnitTests/Intel/Decoder/DecoderTest64.txt), [iced decoder tests](https://github.com/icedland/iced/tree/master/src/UnitTests/Intel/Decoder))
- Zydis uses a decoder tree of 16-bit nodes. Filter nodes select on opcode table, mode, ModRM fields, mandatory prefix, operand size, address size, vector length, REX.W and REX.B. Leaf definitions hold displacement and immediate sizes per size class. Fuzzers decode, re-encode and compare. ([Zydis DecoderData.h](https://raw.githubusercontent.com/zyantific/zydis/master/include/Zydis/Internal/DecoderData.h), [Zydis tests](https://github.com/zyantific/zydis/tree/master/tests), [Zydis tools](https://github.com/zyantific/zydis/tree/master/tools), [Zydis InstructionEditor](https://git.x64dbg.cn/x64dbg/zydis/src/commit/a636fa353e514d57e56f61be982b73533231dd53/assets/InstructionEditor))
- yaxpeax-x86 decodes about 250 MB/s with unchecked indexing. Its `Operand` enum has 27 variants, one per addressing mode, and AVX-512 masks double the count. One memory struct with optional fields scales better. ([yaxpeax-x86](https://github.com/iximeow/yaxpeax-x86), [yaxpeax-x86 Operand](https://docs.rs/yaxpeax-x86/latest/yaxpeax_x86/long_mode/enum.Operand.html), [yaxpeax-arm Operand](https://docs.rs/yaxpeax-arm/latest/yaxpeax_arm/armv8/a64/enum.Operand.html))
- Capstone auto-sync translates LLVM TableGen output to C. LLVM fixed-length decoders run a bytecode: `ExtractField`, `FilterValue`, `CheckField`, `CheckPredicate`, `Decode`, `TryDecode`, `SoftFail`, `Fail`. This is a direct model for AArch64 and RISC-V tables. MC tests pair `# CHECK:` text with bytes. ([Capstone auto-sync](https://fuchsia.googlesource.com/third_party/capstone/+/upstream/next/suite/auto-sync/README.md), [Capstone suite](https://fuchsia.googlesource.com/third_party/capstone/+/upstream/next/suite), [LLVM MCD](https://llvm.org/doxygen/namespacellvm_1_1MCD.html), [MCDecoderOps.h](https://code.woboq.org/llvm/llvm/include/llvm/MC/MCDecoderOps.h.html), [LLVM AArch64 MC test](https://raw.githubusercontent.com/llvm/llvm-project/main/llvm/test/MC/Disassembler/AArch64/basic-a64-instructions.txt))
- mishegos runs decoders as workers and groups the results of one input into a "cohort". Its sliding mutator stresses prefixes. It reports three classes: different lengths, one decoder fails, same length with different fields. Its authors say that no decoder is ground truth. ([mishegos](https://blog.trailofbits.com/2019/10/31/destroying-x86_64-instruction-decoders-with-differential-fuzzing/))
- Measured on 100k random 15-byte inputs (objdump 2.42 vs llvm-objdump 18): agree 42.2%, both invalid 11.8%, different lengths 6.7%, different mnemonic 33.6%. Invalid only in objdump: 1.6%. Invalid only in LLVM: 4.2%. On `/usr/bin/bash` (241,709 instructions) the boundaries match 100%.
- Measured normalizer needs (objdump `-M intel` vs LLVM): unused prefix words, branch target format, unsigned vs signed immediates and negative RIP displacements. Other differences: `fs:0x28` vs `fs:[0x28]`, `riz`, `sar rcx,1` vs `sar rcx`, string-op forms and `66 90`. Use `objdump -d -w -z -M intel`. One label per case makes objdump decode each case from its start.
- Measured x86-64 frequency (2,824,260 instructions from libc, bash, python3.12 and gdb): mov 35.1%, call 7.75, test 5.50, je 5.41, cmp 4.98, jmp 4.85, lea 4.00. 16 mnemonics cover 90%, 68 cover 99% and 153 cover 99.9% of 313. The 1-byte map has 86.5%, 0F 13.1%, VEX 0.26%, EVEX 0.10%. REX is on 47.6%. ([Akshintala et al.](https://par.nsf.gov/servlets/purl/10107613), [cambus](https://cambus.net/assembly-instructions-distribution), [strchr](https://www.strchr.com/x86_machine_code_statistics))
- AArch64 top level: op0 is bit 31 and op1 is bits[28:25]. 100x is DP immediate, 101x is branches and system, x101 is DP register, x111 is FP/SIMD, x1x0 is loads and stores, 0010 is SVE. Inside DP immediate, bits[25:22] select ADR/ADRP, add/sub, logical, move wide, bitfield and extract. ([A64 encoding index](https://www.scs.stanford.edu/~zyedidia/arm64/encodingindex.html), [binutils sim decode.h](https://gnu.googlesource.com/binutils-gdb/+/master/sim/aarch64/decode.h))
- Measured AArch64 fields (31 encodings matched llvm-mc): ADD imm `sf|op|S|100010|sh|imm12|Rn|Rd`. MOVZ/MOVN/MOVK `sf|opc|100101|hw|imm16|Rd`. ADRP target `(PC&~0xfff)+(sext(immhi:immlo)<<12)`. LDP/STP `opc|101|V|mode|L|imm7|Rt2|Rn|Rt`. B/BL `op|00101|imm26`. B.cond `01010100|imm19|0|cond`. RET is `d65f03c0`. Hardened code has `paciasp d503233f` and `bti c d503245f`.
- AArch64 aliases: CMP is SUBS with Rd=31. MOV (register) is ORR with Rn=31. MOVZ prints as MOV except when imm16==0 and hw!=0. UBFM becomes LSL, LSR, UBFIZ, UBFX or UXTB/UXTH by field rules. CSET is CSINC with Rm=Rn=31 and prints the inverted condition. ([SUBS](https://www.scs.stanford.edu/~zyedidia/arm64/subs_addsub_shift.html), [MOVZ](https://www.scs.stanford.edu/~zyedidia/arm64/movz.html), [MOVN](https://www.scs.stanford.edu/~zyedidia/arm64/movn.html), [ORR shifted](https://www.scs.stanford.edu/~zyedidia/arm64/orr_log_shift.html), [ORR imm](https://www.scs.stanford.edu/~zyedidia/arm64/orr_log_imm.html), [UBFM](https://www.scs.stanford.edu/~zyedidia/arm64/ubfm.html), [SBFM](https://www.scs.stanford.edu/~zyedidia/arm64/sbfm.html), [CSINC](https://www.scs.stanford.edu/~zyedidia/arm64/csinc.html), [ADD imm](https://www.scs.stanford.edu/~zyedidia/arm64/add_addsub_imm.html))
- `DecodeBitMasks` for logical immediates: `len = HighestSetBit(N:NOT(imms))`. The encoding is reserved if len<1 or `(imms&levels)==levels`. Measured: a 15-line port matched llvm-mc on all 10,240 AND-immediate encodings.
- Measured AArch64 frequency (113,356 instructions, clang 18 -O2): add 13.3%, mov 12.4, ldr 10.5, cmp 9.5, sub 5.5, str 5.4, b 3.9. About 29 mnemonics cover 90%, and fewer than 45 cover 96%.
- RISC-V: an instruction is 16 bits if `inst[1:0]!=11`, else 32 bits. Base opcodes are in bits [6:0]. Immediate layouts I, S, B, U and J always take the sign from bit 31. RV64 shifts use a 6-bit shamt. C registers rd'/rs1'/rs2' select x8-x15. The all-zero halfword is illegal. Measured: 54.5% of clang riscv64 -O2 instructions are compressed. ([RISC-V C extension](https://docs.riscv.org/reference/isa/v20260120/unpriv/c-st-ext.html), [RV32I base](https://docs.riscv.org/reference/isa/v20260120/unpriv/rv32.html))
- Measured oracles on the host: objdump 2.42 knows x86 only. LLVM 18 llvm-mc and llvm-objdump know x86-64, aarch64 and riscv64. gdb 15 is not multi-architecture. x86 has two independent oracles. AArch64 and RISC-V have only LLVM.
- SLEIGH specs contain errors. InSPECtor executed decoded forms on hardware and in spec emulation and found 125 unique bugs in x86-64, AArch64, ARM, RISC-V and MSP430 specs. A lifter needs its own differential test against execution. ([SLEIGH manual](https://ghidra.re/ghidra_docs/languages/html/sleigh.html), [InSPECtor](https://arxiv.org/abs/2608.13042))

#### Design implications

- x86 layer 1 is a structural decoder: prefixes, REX/VEX/EVEX/REX2, map, opcode, ModRM, SIB, displacement and immediate sizes. It always returns a length or a typed error, so a linear sweep keeps its position. Layer 2 maps the result to mnemonic and operands through tables.
- Each instruction keeps `RawFields` (prefix bytes, REX, VEX fields, ModRM, SIB, displacement and immediate offset and size). Patches and `explain` output use them.
- Typed errors: `Truncated{have, need_at_least}`, `Invalid{len_consumed, reason}`, `InvalidInMode{mode}` and `Unsupported{feature}`. An unsupported instruction with a known length still advances the sweep.
- x86 tables are checked-in Rust const arrays in Intel SDM operand notation (Eb, Ev, Gv, Ib, Iz, Jb, Jz). Entry flags are d64, f64, i64, o64, lock_ok, rep_ok and has_modrm. Shapes: `MAP0: [Entry; 256]`, `MAP1: [[Entry; 4]; 256]` and group tables `[Entry; 8]`.
- AArch64 dispatches on op1 and RISC-V on opcode[6:0], then on ordered `(mask, value, decode_fn)` lists or nested `match`. Keep `bits(w, hi, lo)` and `sext(v, n)` in one place and test them exhaustively.
- One operand model for all ISAs: `Reg{reg, access}`, `Imm{value: i64, width, signed}`, `Mem{seg, base, index, scale, disp, width_bytes, addr_width, writeback, abs_target}`, `Target{addr}`, `ShiftedReg`, `ExtendedReg`, `Cond` and `Sys`. The memory width is on the operand.
- `Reg` packs into a u16 (class, number, width, byte offset) with `full()`, `bit_range()` and `write_zero_extends()`. Implicit register reads and writes and flags read and written are sets (RSP for push/pop, RAX/RDX for mul/div, NZCV for S-forms).
- The decoder emits the canonical operation (SUBS, ORR, UBFM, CSINC, ADDI). A pure printer `fn(&Insn, Syntax)` applies the alias rules. JSON has `mnem` (canonical) and `text` (display), so agents never parse display text.
- Options: `amd_branch_osz`, `strict_vex_legacy_prefix`, `reserved_nop_hints`, `apx` and an `objdump_compat` printer. Differential tests can then target each oracle exactly.
- Compact JSONL per instruction, for example `{"a":"0x401000","n":3,"b":"4889e5","m":"mov","t":"mov rbp, rsp","f":"seq"}`. Flow kinds: seq, jmp, jcc, call, icall, ijmp, ret, trap and invalid.
- Order of work: (1) x86 length decoder for all maps. (2) General-purpose x86 set (99% of code), then common SSE, then VEX. (3) AArch64 base integer set with aliases. (4) RV64IMAC + Zicsr; a compressed form decodes to its base form with `len=2`. (5) Printers. (6) Golden files.
- Tests: unit tests from the spec in the iced line format, independent of oracles. Real-code differential tests gate on 100% boundary agreement on `/usr/bin` and libc. Structured enumeration over ModRM × SIB × REX × prefixes uses a reviewed divergence allowlist.
- Tests: random fuzz tests only properties: no panic, len ≤ 15, deterministic, `decode(bytes[..len]) == decode(bytes)`, `Truncated` on cut input, at least 1 byte consumed. AArch64 tests use llvm-mc with and without `-M no-aliases`. RISC-V tests cover all 65,536 halfwords.
- Generator scripts (python3 `-I` or std-only Rust bins) write `tests/golden/*.txt`. Plain `cargo test` reads only the golden files.

#### Pitfalls

- Do not compare display strings between oracles. They agree on only 42% of random first instructions. Normalize, or compare structured fields.
- `[r12]` and `[rsp]` need a SIB. `[r13]` and `[rbp]` need disp8=0. SIB index=100 means "no index" only with REX.X=0.
- Without a vendor option, 66 near branches cause false mismatches (AMD vs Intel rule).
- Immediate width is not operand width. `Iz` is 32 bits, sign-extended.
- LOCK is valid only on memory-destination read-modify-write forms. The oracles print an invalid LOCK in different ways.
- objdump collapses zero runs to `...` without `-z` and wraps bytes without `-w`. llvm-mc prints relative branch offsets, but llvm-objdump prints absolute targets.
- AArch64: decide SP vs ZR per encoding class. Inverted-condition aliases are not allowed for cond 111x. mov and cmp are 22% of AArch64 code, so a wrong alias rule gives a constant mismatch rate.
- Logical immediates with an all-ones pattern are reserved. With sf=0, N=1 is undefined.
- RISC-V C.JAL/C.ADDIW and C.FLW/C.LD differ between RV32 and RV64. The decoder needs XLEN as input.
- Unchecked indexing (as in yaxpeax) can crash on hostile input. Use safe Rust with bounds tests, and fuzz for no panic.
- Put the NOP hint space (`0F 18-1F`, `F2 0F 1E FA`), VEX with legacy prefixes and APX on a documented allowlist, not in hard asserts.

### 3.5 IR and lifter design

#### Findings

- Ghidra P-code is a flat three-address IR. A varnode is `(space, offset, size)` with no type. Spaces are ram, register, const and unique. There are 64 raw opcodes. LOAD takes a space ID, and the output size sets the width. A BRANCH to the const space jumps inside one instruction. CALL and RETURN are hints only. ([pcoderef](https://github.com/NationalSecurityAgency/ghidra/blob/master/GhidraDocs/languages/html/pcoderef.html), [pcodedescription](https://github.com/NationalSecurityAgency/ghidra/blob/master/GhidraDocs/languages/html/pcodedescription.html))
- P-code compares give a 1-byte boolean. PIECE puts input0 in the high bytes. SUBPIECE input1 is the count of low bytes to drop. Analysis-only ops are MULTIEQUAL (phi), INDIRECT, PTRADD, PTRSUB, CAST and INSERT. SeqNum (address, uniq) is a stable op ID. ([additionalpcode](https://github.com/NationalSecurityAgency/ghidra/blob/master/GhidraDocs/languages/html/additionalpcode.html), [address.hh](https://raw.githubusercontent.com/NationalSecurityAgency/ghidra/master/Ghidra/Features/Decompiler/src/decompile/cpp/address.hh))
- Ghidra x86 SLEIGH flags are eager 1-byte registers at offset 0x200 (CF, PF, AF, ZF, SF, OF). One `CMP` gives about 10 p-code ops. `resultflags` computes no AF. Sub-registers alias by offset: RAX/EAX/AX/AL at 0, AH at 1, RIP at 0x280. ([ia.sinc](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Processors/x86/data/languages/ia.sinc))
- Ghidra repairs eager flags after SSA with rules: RuleSborrow (`sborrow(V,W) != (V-W s< 0)` becomes `V s< W`), RuleLessEqual, RuleEqual2Zero and RuleBoolNegate. ActionDeadCode removes unread flags. ActionMarkExplicit makes a varnode a variable only for symbols, aliases or many reads. Other varnodes print inline. ([ruleaction.cc](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Features/Decompiler/src/decompile/cpp/ruleaction.cc), [coreaction.hh](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Features/Decompiler/src/decompile/cpp/coreaction.hh))
- VEX uses single-entry, multiple-exit superblocks (IRSBs). Temps are SSA inside a block. Guest registers are byte offsets in a state struct. Each exit has a jump kind. The IROp enum has about 1,650 lines, mostly SIMD. amd64 flags are a lazy thunk `CC_OP, CC_DEP1, CC_DEP2, CC_NDEP` that helper calls read. ([libvex_ir.h](https://github.com/angr/vex/blob/master/pub/libvex_ir.h), [libvex_guest_amd64.h](https://raw.githubusercontent.com/angr/vex/master/pub/libvex_guest_amd64.h))
- MeanDiff N-version differential tests found 24 unknown semantic bugs in BAP, BINSEC and PyVEX, 4 of them in VEX. ([MeanDiff](https://softsec.kaist.ac.kr/~soomink/paper/ase17main-mainp491-p.pdf), [KDE bug 384842](https://bugs.kde.org/show_bug.cgi?id=384842))
- Thunk enums (a design source only, because VEX is GPL-3.0+): `AMD64G_CC_OP` is `COPY=0 ADD=1-4 SUB=5-8 ADC=9-12 SBB=13-16 LOGIC=17-20 INC=21-24 DEC=25-28 SHL=29-32 SHR=33-36`, then ROL, ROR, UMUL, SMUL and BMI ops up to 64. `AMD64Condcode` 0-15 has the Jcc low-nibble order. ARM64 cond is EQ..NV. ([guest_amd64_defs.h](https://github.com/angr/vex/blob/master/priv/guest_amd64_defs.h), [guest_arm64_defs.h](https://github.com/angr/vex/blob/master/priv/guest_arm64_defs.h), [VEX license](https://github.com/angr/vex/blob/master/LICENSE.README))
- angr Clinic lifts VEX to AIL trees in stages. The first stages are return sites, argument lists, stack pointer tracking, SSA level 0 (registers), constant propagation and call sites. Then come SSA level 1 (stack variables), simplification and variable recovery. SP tracking runs before SSA. The AIL core is now Rust. ([clinic.py](https://github.com/angr/angr/blob/master/angr/analyses/decompiler/clinic.py), [AIL statement.py](https://github.com/angr/angr/blob/master/angr/ailment/statement.py), [AIL expression.py](https://github.com/angr/angr/blob/master/angr/ailment/expression.py), [ssailification.py](https://github.com/angr/angr/blob/master/angr/analyses/decompiler/ssailification/ssailification.py))
- angr rewrites flag helper calls into compares after simplification. Examples: `(SUB, CondLE)` becomes signed `CmpLE`, and `(LOGIC, CondZ)` becomes `CmpEQ(dep1, 0)`. Unhandled pairs keep the helper call. A source review found a width bug in the `(DEC, CondZ)` arm. ([amd64_ccalls.py](https://github.com/angr/angr/blob/master/angr/analyses/decompiler/ccall_rewriters/amd64_ccalls.py), [ail_simplifier.py](https://github.com/angr/angr/blob/master/angr/analyses/decompiler/ail_simplifier.py))
- Binary Ninja keeps flag conditions only in Lifted IL. It makes flag IL only for flags that something reads. Architectures declare flag roles and write types. Semantic conditions (`LLFC_E`, `SLT`, `ULT` and others) let the core put compares into branches. MLIL has typed variables and SSA. ([binaryninjacore.h](https://github.com/Vector35/binaryninja-api/blob/dev/binaryninjacore.h), [BN flags](https://docs.binary.ninja/dev/flags.html), [BNIL overview](https://docs.binary.ninja/dev/bnil-overview.html), [BN LLIL](https://docs.binary.ninja/dev/bnil-llil.html), [BN MLIL](https://docs.binary.ninja/dev/bnil-mlil.html), [BN flag.rs](https://rust.binary.ninja/src/binaryninja/architecture/flag.rs.html))
- dewolf starts from MLIL-SSA. It runs expression propagation, DCE and CSE on the CFG, then refinement on the AST. ([dewolf default.py](https://github.com/fkie-cad/dewolf/blob/main/decompiler/pipeline/default.py), [dewolf paper](https://arxiv.org/pdf/2205.06719))
- Other IRs: radare2 ESIL is a string RPN language (`3,eax,=`) that is hard for dataflow. REIL has 17 instructions. Falcon (Rust) has 6 operations (Assign, Store, Load, Branch, Intrinsic, Nop) and about 23 expression kinds. ([esil(7)](https://man.archlinux.org/man/esil.7.en), [REIL blog](https://blog.zynamics.com/2010/03/07/the-reil-language-part-i), [REIL manual](https://zynamics.com/binnavi/manual/html/reil_language.htm), [Falcon expression.rs](https://raw.githubusercontent.com/falconre/falcon/master/lib/il/expression.rs), [Falcon operation.rs](https://raw.githubusercontent.com/falconre/falcon/master/lib/il/operation.rs))
- Eager lifters need a later pattern pass. RetDec stores i1 flags, then `CondBranchOpt` matches `ZF SF OF xor or` into `icmp sle`. Falcon and BAP also set flags eagerly. rev.ng lifts QEMU TCG with its lazy `cc_op` state. ([RetDec x86.cpp](https://github.com/avast/retdec/blob/master/src/capstone2llvmir/x86/x86.cpp), [CondBranchOpt](https://github.com/avast/retdec/blob/master/src/bin2llvmir/optimizations/cond_branch_opt/cond_branch_opt.cpp), [Falcon il](https://github.com/falconre/falcon/blob/master/lib/il/mod.rs), [Falcon x86 semantics](https://github.com/falconre/falcon/blob/master/lib/translator/x86/semantics.rs), [BAP x86 lifter](https://github.com/BinaryAnalysisPlatform/bap/blob/master/plugins/x86/x86_lifter.ml), [rev.ng helpers](https://docs.rev.ng/developer-manual/qemu-helpers/))

- Measured AArch64 NZCV (libzstd, clang-18 -O2, 103,225 instructions): 11.2% are writers, and all writers are live, because flag setting is opt-in. 32.8% of eager N, Z, C, V bits are read. Readers: b.cond 9,228, csel family 2,331, ccmp/ccmn 217. 8.7% of reads have a source register changed between cmp and reader. CBZ/CBNZ/TBZ/TBNZ are 16.9% of conditional branches.
- Verdict from the numbers. Eager flags (Ghidra style) give about 10 ops per CMP, and 86-91% of the bits are dead on x86. Fusion at lift time is wrong for gap-changed reads unless it snapshots operands, and it cannot show carry chains or reads in other blocks. A lazy thunk with snapshot args is exact and fuses through a closed table.
- x86 semantic sources: the Intel SDM pseudocode and "Flags Affected" sections are normative but proprietary, so transcribe semantics, not text. remill (Apache-2.0) tests lifted against native with flag permutations. K X86-64 semantics (NCSA) covers 3,155 variants and was co-simulated with hardware. ([Intel SDM](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html), [remill](https://github.com/lifting-bits/remill), [remill ADD_AN_INSTRUCTION](https://github.com/lifting-bits/remill/blob/master/docs/ADD_AN_INSTRUCTION.md), [K X86-64](https://github.com/kframework/X86-64-semantics), [K license](https://github.com/kframework/X86-64-semantics/blob/master/LICENSE.md), [Dasgupta PLDI'19](https://fsl.cs.illinois.edu/publications/dasgupta-park-kasampalis-adve-rosu-2019-pldi.pdf), [pcodetest README](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Extensions/SleighDevTools/pcodetest/README.txt))
- AArch64 semantics: ASL `AddWithCarry(x, y, carry_in)` gives N = result<N-1>, Z = IsZero, C = unsigned overflow, V = signed overflow. SUBS is `AddWithCarry(x, NOT(y), 1)`, so C=1 means no borrow, the inverse of x86 CF. CCMP sets the compare flags when its condition holds, else `#nzcv`. ([A64 ADCS](https://www.scs.stanford.edu/~zyedidia/arm64/adcs.html), [AARCHMRS](https://kernel.googlesource.com/pub/scm/linux/kernel/git/maz/AARCHMRS/+/HEAD), [Reid FMCAD'16](https://fmcad.forsyte.at/FMCAD16/slides/s4t3.pdf), [AARCH64instructions.sinc](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Processors/AARCH64/data/languages/AARCH64instructions.sinc))
- Measured prototype: a std-only native oracle works. It maps an RWX page with `extern "C" mmap`. An `asm!` trampoline loads registers and RFLAGS from a `#[repr(C)]` struct, calls the instruction bytes plus `C3` and saves the state. `sub rax,rbx` matched the Rust model of all six status flags on 100 of 100 edge cases. ([Rust inline assembly](https://doc.rust-lang.org/reference/inline-assembly.html))
- ptrace co-simulation needs only std plus `extern "C"`: `PTRACE_TRACEME=0 PEEKDATA=2 POKEDATA=5 CONT=7 SINGLESTEP=9 GETREGS=12 SETREGS=13`. `user_regs_struct` is 27 u64 (216 bytes); rip is index 16, eflags 18, rsp 19. Call TRACEME from `CommandExt::pre_exec`. No qemu-aarch64 exists on the host. ([ptrace(2)](https://man7.org/linux/man-pages/man2/ptrace.2.html))
- Measured x86-64 v1 coverage of the core integer set: bash 99.35%, libc 93.46%, zstd-gcc 96.71% and zstd-clang 95.46%. The set has moves, ALU ops, mul/div, shifts, bit ops, cmpxchg/xadd, branches, setcc/cmovcc, string ops, flag ops and BMI. Opaque SSE moves and logic raise this to 99.99/97.18/99.27/98.87%.
- Braun SSA fits a Get/Put IR directly: `Get(loc)` is `readVariable` and `Put(loc,t)` is `writeVariable`. Temps are already single-assignment. Locations in v1 are full-width registers, Flags and `Stack(k)`. ([Braun CC 2013 PDF](https://bernsteinbear.com/assets/img/braun13cc.pdf), [Braun DOI](https://link.springer.com/chapter/10.1007/978-3-642-37051-9_6), [Braun project page](https://www.compilers.cs.uni-saarland.de/projects/ssaconstr/))

#### Design implications

- Decision: one pipeline. L0 is a flat VEX-style lifted IR with about 50 opcodes and single-def temps. `Get`/`Put` are the only ops on architectural locations. Flags are a lazy thunk `Flags(op, a, b, c)` that `Cond(cc, ·)` reads. L1 is the same arena after Braun SSA (Get/Put replaced by values and `Phi`).
- Types: `OpId{addr: u64, seq: u16}` (text `0x401a2c:3`; seq 0..0x7FFF from the lifter, 0x8000.. from passes, 0xF000+k for phis). `Loc{Reg(u16), Flags, Stack(i32)}`. `Val(u32)`. `Arg{V(Val), K(u64)}`. `Op{id, opc, w, out: Option<Val>, a: [Arg; 3]}`. A test asserts `size_of::<Op>() <= 64`.
- Opcodes: `Get Put Copy Load Store Add Sub Mul UMulHi SMulHi UDiv SDiv URem SRem Neg Not And Or Xor Shl LShr AShr Rol Ror ZExt SExt Trunc Extract Insert Popcnt Clz Ctz Bswap Eq Ne ULt ULe SLt SLe Ite Flags Cond FlagsSel FlagsGet FlagsSet Jump CJump JumpInd Call CallInd Ret Intrinsic Unimpl Nop Phi`.
- `FlagOp` is per ISA: `X86Add X86Sub X86Adc X86Sbb X86Logic X86Inc X86Dec X86Neg X86Shl X86Shr X86Sar X86Rol X86Ror X86UMul X86SMul X86Bt ... A64Add A64Sub A64Adc A64Sbc A64Logic Copy`. `Cc` is `X86(u8)` (Jcc low nibble) or `A64(u8)` (EQ..NV). Do not share a canonical carry bit between ISAs.
- One semantic module is the source of truth: `x86_flags(op, w, a, b, c) -> u16` (CF=bit 0, PF=2, AF=4, ZF=6, SF=7, OF=11), `x86_cond`, `a64_nzcv` (N=8, Z=4, C=2, V=1), `a64_cond` and `fuse(op, cc, a, b) -> Option<(Opc, Arg, Arg)>`. The emulator, materialization and fusion all use it.
- `FlagsSel(c, f1, f2)` models CCMP and shift-by-CL with count 0. `FlagsGet`/`FlagsSet` pack and unpack for PUSHF/POPF/LAHF/SAHF and MRS/MSR NZCV. The `c` input of `Flags` carries carry-in or the previous flags (needed by INC/DEC/BT).
- Registers are full width only. A 32-bit write is `Put(ZExt)`. An 8- or 16-bit write is `Insert` into `Get(Reg)`. Reads use `Trunc` or `Extract`. No varnode overlap logic is needed.
- Pass order (one interpreter runs both L0 and L1):
  1. Decode.
  2. Lift to L0.
  3. Block-local Get-after-Put forwarding, constant fold, `Cond(cc, Flags(..))` fusion, dead-flag removal and DCE.
  4. CFG and jump tables on L0.
  5. SP tracking on L0.
  6. Stack slots become `Stack(k)` when the address does not escape.
  7. Braun SSA with SCC phi cleanup.
  8. SCCP, copy propagation, `Cond` through flag phis, materialization of left-over flag reads and DCE.
  9. Calling convention and arguments.
  10. Expression view.
  11. Structurer.
  12. Pseudo-C and JSON.
- Expression view (output only, rebuilt on demand): `Expr{Var, K, Load, Un, Bin, Ite, Call}` with an `OpId` on each node. `Stmt{Assign, Store, Call, If, Loop, Switch, Return, Goto, Break, Continue}`. Single-use pure defs are inlined (Ghidra implied rule). A Load never moves across a Store or a Call.
- AArch64: ADDS/SUBS/CMP/CMN/ADCS/SBCS/ANDS/TST lift to `Flags(A64*)`. B.cond lifts to `CJump(Cond)`. The CSEL family lifts to `Ite(Cond)`. CCMP lifts to `FlagsSel(Cond(cc, prev), Flags(A64Sub, a, b), Flags(Copy, imm<<28))`. A rewrite then simplifies `Cond` over `FlagsSel` into `c && x` or `!c || x`.
- Stable IDs: SSA values and expression nodes take their names from the defining `OpId`. Store `lift_ver` with each ID. Passes take seq numbers from a counter per address in a fixed pass order. JSON form: `{"addr":"0x401a2c","seq":3}`.
- Milestones: M1 decoder and L0 lifter for the core integer set, other instructions as `Intrinsic` or `Unimpl`. M2 semantic module and native oracle. M3 fusion table, exhaustive at w=8. M4 CFG, jump tables, SP on L0. M5 SSA, SCCP, expressions, structurer. M6 (v2) memory SSA, float, x87, AVX-512.
- Tests T1-T2: an in-process native oracle per instruction form (edge values × CF × widths, plus 10k random cases), with undefined flags masked. Exhaustive fusion test: for each (FlagOp, Cc) and all 8-bit a, b and c in {0,1}, `fuse` equals `x86_cond(cc, x86_flags(..))`. The same for A64.
- Tests T3-T5: ptrace single-step co-simulation of gcc/clang corpus binaries. End-to-end: emulate lifted functions on random inputs and compare with native output. AArch64 has a cross-ISA differential with the x86-64 native result. The decoder differential covers all of bash and libc `.text`.
- Tests T6-T7: re-run the flag-shape statistics on L0 and assert fusion of at least 98% of reads. Compare recovered jump-table targets with compiler `.rodata` tables.

#### Pitfalls

- A shift or rotate by CL with a masked count of 0 leaves all flags unchanged. Model it with `FlagsSel(cnt==0, prev, new)`. The count mask is 5 bits (6 bits for 64-bit operands).
- INC/DEC keep CF, and BT writes only CF in practice. The thunk needs the previous flags as input `c`.
- Undefined flags: IMUL SF/ZF/AF/PF, BSF/BSR CF/OF/SF/AF/PF, OF for shifts by more than 1, AF for logic ops. Mask them in differential tests. Do not let an undefined flag feed fusion.
- Ghidra `ia.sinc` computes no AF. Do not use Ghidra as the AF or PUSHF oracle.
- AArch64 C after SUBS is NOT borrow (HS means a ≥u b). A shared canonical carry bit silently inverts unsigned compares.
- clang schedules cmp far from b.cond. Fusion that reads registers again at the reader is wrong for 8.7% of A64 reads and 0.6-3.4% of x86 reads. Thunk arguments must be snapshot temps.
- In the `asm!` harness, rbx cannot be an operand. With `clobber_abi("C")`, `out(reg) _` becomes a lateout and can share a register with an input. Pin the operands to explicit registers.
- Licenses: do not copy VEX (GPL-3.0+) or QEMU code. Intel SDM and the full Arm ASL text are proprietary; transcribe semantics only.
- Braun SSA is minimal only for reducible CFGs. libc asm and jump threading make irreducible regions, so run the SCC phi cleanup.
- angr's hand-written flag table had a width bug. Test every (FlagOp, Cc) fusion entry exhaustively against the bit semantics.
- The flag measurements use an objdump linear sweep and treat calls as flag kills. The numbers can shift by a few tenths of a percent.

### 3.6 Function discovery, CFG and dataflow algorithms

#### Findings

- Andriesse et al. (981 binaries): linear sweep recovers 100% of instructions for gcc and clang, because these compilers put no data in `.text`. MSVC inline jump tables give up to 0.56% false instructions. Function starts are the hard part: the best tools fall from about 99% at O0 to 82% at O3. No compiler output had overlapping blocks. ([Andriesse 2016](https://www.usenix.org/system/files/conference/usenixsecurity16/sec16_paper_andriesse.pdf), [VUSec disassembly](https://www.vusec.net/projects/disassembly/))
- SoK (Pang et al., 3,788 binaries): pure recursive descent has about 99.5% precision but about 51% recall. Prologue matching adds 17.36% more functions at 77.53% mean precision. Linear sweep has 99.95% recall, but objdump precision falls to 85.35% on OpenSSL asm. Ghidra resolves more than 93% of jump tables at about 90% precision. ([SoK](https://arxiv.org/pdf/2007.14266), [SoK mirror](https://softsec.cs.utah.edu/papers/x86SoK.pdf))
- Seeds per tool: all tools use the entry, `.symtab`/`.dynsym` and direct call targets. angr and BAP find `main` from the first argument of `__libc_start_main`. Only Ghidra uses `.eh_frame` FDEs. Ghidra needs at least 2 consecutive pointers for an address table. 99.94% of Ghidra false starts come from FDEs that point into function middles. ([SoK](https://arxiv.org/pdf/2007.14266))
- FETCH: FDEs cover 99.87% of compiler-made function starts (1,103,832 of 1,105,278). FDEs also gave 34,772 false starts, nearly all from split hot/cold functions. Tail-call and merge rules cut false positives to 2,659, at a cost of 161 misses. Prologue matching added 4,128 false positives. ([FETCH](https://arxiv.org/pdf/2104.03168), [FETCH ar5iv](https://ar5iv.labs.arxiv.org/html/2104.03168))
- FETCH tail-call rule: a jump is a tail call only if three conditions are true. The stack height is 0. The target obeys the calling convention. Only jumps from this function refer to the target. Otherwise, merge the FDE-only target into the caller as a part. ([FETCH](https://arxiv.org/pdf/2104.03168))
- Measured (gcc 13.3 -O2): `die` branches to `die.cold` in `.text.unlikely`, which has its own FDE. `.eh_frame_hdr` starts with `01 1b 03 3b`: version 1, `eh_frame_ptr_enc=0x1b`, `fde_count_enc=0x03`, `table_enc=0x3b`. A sorted table of `(initial_loc, fde_addr)` pairs follows the count. ([LSB exception frames](https://refspecs.linuxfoundation.org/LSB_5.0.0/LSB-Core-generic/LSB-Core-generic/ehframechpt.html))
- CIE/FDE format: a 4-byte length (0xffffffff means a 64-bit length follows, 0 ends the list). The CIE ID is 0 in `.eh_frame`. The FDE CIE pointer is a backward offset. The augmentation (`zR`, `zPLR`) sets the pointer encoding. `DW_EH_PE` values: `absptr=0 uleb128=1 udata2=2 udata4=3 udata8=4 sleb128=9 sdata2=0xa sdata4=0xb sdata8=0xc pcrel=0x10 datarel=0x30 indirect=0x80 omit=0xff`. ([LSB exception frames](https://refspecs.linuxfoundation.org/LSB_5.0.0/LSB-Core-generic/LSB-Core-generic/ehframechpt.html))
- PE `UNWIND_CODE` ops: PUSH_NONVOL=0, ALLOC_LARGE=1, ALLOC_SMALL=2 (info*8+8), SET_FPREG=3, SAVE_NONVOL=4, SAVE_NONVOL_FAR=5, SAVE_XMM128=8, SAVE_XMM128_FAR=9, PUSH_MACHFRAME=10. Registers 0-15 are RAX, RCX, RDX, RBX, RSP, RBP, RSI, RDI, R8-R15. Unwind codes give the true prolog stack size. ([x64 exception handling](https://learn.microsoft.com/en-us/cpp/build/exception-handling-x64))
- Nucleus finds functions without signatures. It sweeps blocks, resolves switches, marks padding and suspect data, removes call edges and takes connected components. A component with a direct-call target is that function. Function-start F-score is 0.96 on SPEC. 96% of sampled false positives came from tail calls. ([Nucleus](https://mistakenot.net/papers/eurosp-2017.pdf), [VUSec function detection](https://www.vusec.net/projects/function-detection/), [BN function detection](https://binary.ninja/2017/11/06/architecture-agnostic-function-detection-in-binaries.html))
- CET: 99.85% of non-static functions start with `endbr64` (89.3% of all functions). `endbr64` also follows calls to setjmp-like functions and starts C++ catch blocks. endbr heads plus direct call targets plus tail-call targets cover 99.99%. Measured: gcc 13 emits `notrack jmp rax` for switches. ([FunSeeker paper](https://softsec.kaist.ac.kr/~sangkilc/papers/kim-dsn2022.pdf), [FunSeeker](https://github.com/B2R2-org/FunSeeker))
- Ghidra prologue patterns pair masked pre-patterns (padding, `c3 90`, `c9 c3`) with post-patterns (`554889e5`, `415741564155`), each with an ENDBR64 copy. They are good only as a low-confidence fallback for gaps. ([x86-64gcc_patterns.xml](https://raw.githubusercontent.com/NationalSecurityAgency/ghidra/master/Ghidra/Processors/x86/data/patterns/x86-64gcc_patterns.xml))
- Jump tables: Ghidra collects all paths to BRANCHIND, takes guard bounds as ranges and emulates the single data path per index (max 1024 entries). 62.63% of its misses come from no `sub` support in bound analysis. Dyninst slices at most 50 assignments. angr uses at most 4 slice levels. radare2 has 4 patterns. ([jumptable.hh](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Features/Decompiler/src/decompile/cpp/jumptable.hh), [funcdata_block.cc](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Features/Decompiler/src/decompile/cpp/funcdata_block.cc), [Meng and Miller](https://ftp1.cs.wisc.edu/par-distr-sys/papers/Meng15Parsing.pdf), [angr jumptable.py](https://github.com/angr/angr/blob/master/angr/analyses/cfg/indirect_jump_resolvers/jumptable.py))
- Jump tables do not need SSA. angr uses backward slices with simple register and stack tracking. Dyninst uses a backward slice and builds address ASTs. Measured gcc 13 and clang 18 `-O2 -fPIE`: `cmp edi,6; ja default; lea rdx,[rip+T]; movsxd rax,[rdx+rdi*4]; add rax,rdx; jmp rax`. Entries are 4-byte signed offsets from T. Non-PIC code uses `jmp [T+idx*8]`.
- Tail-call rules fail in known ways. Jump distance (radare2) does not work. Ghidra skips conditional jumps and misses 21.6% of tail calls. Dyninst's stack-teardown rule causes 97% of its false positives. angr requires an unconditional jump, stack height 0 and only jump in-edges. ([SoK](https://arxiv.org/pdf/2007.14266))
- Noreturn: the Ghidra ELF list has exit, abort, longjmp, `__stack_chk_fail`, `__cxa_throw`, `_Unwind_Resume`, `__assert_fail`, `pthread_exit` and others, matched after the leading `_` is removed. The PE list adds ExitProcess, ExitThread, `_CxxThrowException` and KeBugCheckEx. Missed noreturn calls cause 14.16% of Ghidra-NE function misses. ([ElfFunctionsThatDoNotReturn](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Features/Base/data/ElfFunctionsThatDoNotReturn), [PEFunctionsThatDoNotReturn](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Features/Base/data/PEFunctionsThatDoNotReturn))
- Ghidra "Non-Returning Functions - Discovered" marks a callee noreturn when 3 or more call sites have an unsafe fall-through. An unsafe fall-through goes into data, bad code, another function or an xref target. ([FindNoReturnFunctionsAnalyzer](https://raw.githubusercontent.com/NationalSecurityAgency/ghidra/master/Ghidra/Features/Base/src/main/java/ghidra/app/plugin/core/analysis/FindNoReturnFunctionsAnalyzer.java))
- angr stack pointer tracking is forward dataflow with values TOP, BOTTOM and `OffsetVal(base_reg, k)`. A disagreement at a merge gives TOP. It records SP deltas per instruction and adds back the return slot at calls. ([angr StackPointerTracker](https://github.com/angr/angr/blob/master/angr/analyses/stack_pointer_tracker.py))
- Braun et al. SSA: `readVariable` recurses to predecessors, puts operandless phis in unsealed blocks and removes trivial phis. Output is pruned, and minimal for reducible CFGs. An SCC pass cleans irreducible CFGs. It was slightly faster than Cytron in LLVM. Binary CFGs are known up front, so seal all blocks first. ([Braun CC 2013](https://pp.ipd.kit.edu/uploads/publikationen/braun13cc.pdf))
- Wegman-Zadeck SCCP uses TOP, Const and BOTTOM with two worklists (CFG edges and SSA edges), so it prunes branches that never run. Ghidra's constant propagation gave one target for 87,947 of 88,078 resolved indirect calls, so its target sets are incomplete. ([Wegman and Zadeck](https://dl.acm.org/doi/10.1145/103135.103136), [SoK](https://arxiv.org/pdf/2007.14266))
- SysV AMD64: int args RDI RSI RDX RCX R8 R9, FP args XMM0-7, returns RAX:RDX and XMM0:XMM1. It has a 128-byte red zone, and AL bounds the vector registers for varargs. MS x64: args by position in RCX/RDX/R8/R9 or XMM0-3, a 32-byte shadow space, nonvolatile RBX RBP RDI RSI RSP R12-R15 XMM6-15. ([MS x64 calling convention](https://learn.microsoft.com/en-us/cpp/build/x64-calling-convention), [Red zone](https://en.wikipedia.org/wiki/Red_zone_(computing)))
- AAPCS64: x0-x7 are args and results, x8 is the indirect result pointer, x16/x17 are IP0/IP1, x19-x28 are callee-saved, x29 is FP and x30 is LR. Only the low 64 bits of v8-v15 are callee-saved. ([AAPCS64](https://github.com/ARM-software/abi-aa/blob/main/aapcs64/aapcs64.rst))
- angr calling-convention recovery uses known prototypes, callee analysis (registers read before definition) and up to 3 call sites. Varargs prologues read XMM0-7 only to fill the save area. IDA 6.7 got x64 argument counts right only 0.38-1.87% of the time. ([angr calling_convention.py](https://raw.githubusercontent.com/angr/angr/master/angr/analyses/calling_convention/calling_convention.py), [angr cc docs](https://docs.angr.io/en/latest/_modules/angr/analyses/calling_convention.html))
- TIE-style type recovery: a lattice of base types with constraints from use. An address operand is a pointer. A signed compare or division means signed. An FP op means float. Library prototypes give types. Retypd and BinSub add subtyping for records. ([TIE](https://users.ece.cmu.edu/~aavgerin/papers/tie-ndss-2011.pdf), [BinSub](https://arxiv.org/html/2409.01841v1))
- CFG: block leaders are entries, branch targets and the instructions after branches and returning calls. Split a block when a new target lands inside it. Cooper-Harvey-Kennedy dominators are about 30 lines and fast in practice. Most edge errors come from missed noreturn calls, missed tail calls and missed splits. ([Cooper-Harvey-Kennedy](https://www.cs.tufts.edu/comp/150FP/archive/keith-cooper/dom14.pdf), [SoK](https://arxiv.org/pdf/2007.14266))

#### Design implications

- Discovery pipeline in confidence order:
  1. Entry, STT_FUNC symbols, PLT import names and `main` from `__libc_start_main`.
  2. FDE PC Begin and `.pdata`, without CHAININFO entries.
  3. Recursive descent with the noreturn list and propagation.
  4. Direct call targets.
  5. Jump tables.
  6. FETCH tail-call and merge rules for `.cold` parts.
  7. `endbr64` heads that do not follow setjmp-like calls.
  8. Gap fill with Nucleus components or prologue patterns, at low confidence.
- Each function start records its provenance (entry, symbol, fde, pdata, call, tailcall, jumptable, endbr, prologue, gap) and a confidence. Agents filter with `min_confidence` and can see why each function exists.
- CFG: the block ID is the start address. An edge is `{from, to, kind}` with kinds fallthrough, branch, cond_true, cond_false, switch_case(i), call_return, tailcall and indirect_unresolved. An unresolved indirect jump stays as a record, so an agent can supply the targets.
- Jump tables: slice back from JumpInd (max about 50 ops or 4 blocks, stop at calls). Find `base + idx*scale` and the guard. Allow one add/sub normalization. Emulate idx = 0..=N with image-backed loads. Accept only executable targets. Cap at 1024. Support 4-byte relative and 8-byte absolute entries.
- Stack: track SP as an offset from the entry value with TOP/Const values. After a call, apply the callee stack effect (+8 on SysV and MS). Turn `[SP0+k]` accesses into stack variables when the address does not escape.
- Calling conventions are data per ABI: ordered int and float arg lists (positional for MS), stack arg base, return registers, killed set and unaffected set. Params = live-in registers ∩ arg registers, minus callee-saved pairs and alignment pushes, filled up to the highest used register. Compare with call sites.
- Each function result has caveats, for example "jump table at 0x... unresolved" or "noreturn assumed for abort@plt".
- Acceptance targets: instruction boundaries equal objdump for gcc/clang ELF. Function-start F1 is at least 0.98 with `.eh_frame` and at least 0.90 without it. Jump-table targets match `.rela.rodata` for at least 95% of tables. There are zero SSA invariant failures.
- Tests: strip fixtures and compare starts with STT_FUNC symbols of the unstripped copy. Also remove `.eh_frame` and `.eh_frame_hdr` with objcopy. Compare FDE ranges with `readelf --debug-dump=frames`. Jump-table truth is the `R_X86_64_PC32` entries in `.rela.rodata` of `-c` objects.
- Tests: noreturn fixtures (abort, exit, `__stack_chk_fail`, `__assert_fail`, `__cxa_throw`, wrappers). Calling-convention fixtures with known prototypes, also with `__attribute__((ms_abi))`. SSA property tests on random CFGs, irreducible CFGs included.

#### Pitfalls

- An FDE PC Begin is not always a function start (`.cold` parts). On PE, CHAININFO entries are fragments.
- Code after an unconditional jmp or ret that nothing reaches is often a switch case or padding. Resolve jump tables before gap fill.
- A missed noreturn call adds a fall-through edge into the next function and hides function starts. Resolve PLT calls to import names first.
- Do not assume pointer-size jump-table entries. Some indexes have no bound and must stay unresolved.
- Conditional tail calls exist. Jumps between parts of one non-contiguous function look like tail calls.
- Calling-convention false positives: `push rax` for alignment, callee-saved push/pop pairs, varargs `test al,al` prologues and MS shadow-space stores.
- `endbr64` is not always a function start. Static functions that are never address-taken have no `endbr64`.
- Linear sweep is exact only for gcc/clang ELF `.text`. Do not use it as ground truth for hand-written asm or MSVC code.

### 3.7 Decompiler

#### Findings

- Ghidra decompiler order: raw p-code, basic blocks, prototypes and annotation (INDIRECT ops for unknown stack effects). Then a main loop runs SSA, bit-level DCE, type propagation, rewrite rules and loop/if/switch recovery. After the loop: SSA exit and merge, explicit-vs-implied choice, casts, names, final structure and C tokens tagged with source addresses. ([docmain.hh](https://raw.githubusercontent.com/NationalSecurityAgency/ghidra/master/Ghidra/Features/Decompiler/src/decompile/cpp/docmain.hh))
- Ghidra uses Actions (whole-function passes) and Rules (local rewrites), wired in `universalAction`. The main loop holds about 140 rules in pools, for example RuleTermOrder, RuleCollapseConstants, RulePropagateCopy, RuleSborrow and RuleDivOpt. Each action has a group tag (deadcode, typerecovery, blockrecovery, merge, casts) that a pipeline can switch off. ([coreaction.cc](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Features/Decompiler/src/decompile/cpp/coreaction.cc), [Decompiler Doxygen](https://ghidradocs.com/11.1_PUBLIC/docs/DecompilerDoxygen/html/coreaction_8hh.html))
- Ghidra SSA ("heritage") is incremental. Registers link first, and stack locations link on later passes. Phi placement uses Bilardi-Pingali, renaming uses Cytron. Braun SSA plus Cooper-Harvey-Kennedy dominators give the same base in a few hundred lines. ([heritage.hh](https://raw.githubusercontent.com/NationalSecurityAgency/ghidra/master/Ghidra/Features/Decompiler/src/decompile/cpp/heritage.hh), [Braun project page](https://www.compilers.cs.uni-saarland.de/projects/ssaconstr/), [Cooper-Harvey-Kennedy](https://www.cs.tufts.edu/comp/150FP/archive/keith-cooper/dom14.pdf))
- Ghidra DCE is bit-level: a "consumed" mask moves back from fully used seeds (outputs, branch conditions, stores, calls). Other actions remove duplicate edges, constant branches and dead blocks. A minimal design needs only worklist removal of unused pure defs plus lazy flags. ([coreaction.hh](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Features/Decompiler/src/decompile/cpp/coreaction.hh), [dewolf paper](https://arxiv.org/pdf/2205.06719))
- Explicit vs implied: a varnode becomes a named variable when it has no def or is a call output. Many instances, an address tie or more than `max_implied_ref` (2) readers also make it explicit. A LOAD whose live range contains an aliasing STORE or a call becomes explicit again. Defaults: `max_implied_ref=2`, `max_term_duplication=2`, `max_jumptable_size=1024`. ([coreaction.cc](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Features/Decompiler/src/decompile/cpp/coreaction.cc), [architecture.cc](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Features/Decompiler/src/decompile/cpp/architecture.cc))
- angr folds a variable only when it has 1 def and 1 use, and the use is not in a phi. No Store can sit between a load def and its use. No call or side effect can sit between def and use. A def in a loop body folds only if its region-wide uses are at most 1. This is the cheapest correct rule for an MVP. ([region_simplifier.py](https://raw.githubusercontent.com/angr/angr/master/angr/analyses/decompiler/region_simplifiers/region_simplifier.py))
- Out-of-SSA: Ghidra merges SSA varnodes into one variable only when their live ranges do not intersect, like register coloring. dewolf uses three steps. It breaks circular phi dependencies with copies, lifts phis into predecessor copies and renames by interference coloring. ([merge.hh](https://raw.githubusercontent.com/NationalSecurityAgency/ghidra/master/Ghidra/Features/Decompiler/src/decompile/cpp/merge.hh), [dewolf paper](https://arxiv.org/pdf/2205.06719))
- Ghidra type propagation takes local types from the ops that read and write each varnode and pushes them across op edges. The loop may not converge, so Ghidra caps the iterations and warns. Casts come last, only where C syntax needs them. ([coreaction.cc](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Features/Decompiler/src/decompile/cpp/coreaction.cc))
- Ghidra default names come from storage: `param_N`, `in_<REG>`, `unaff_<REG>`, `extraout_<REG>`, `iVar1`/`pcVar3` (type letter plus `p`/`a` prefixes), `local_<hex>` and `<abbr>Stack_<hex>`. DREAM renames a variable to the API parameter name it is passed to. VarBERT reaches 50.70% name accuracy against 38.00% (DIRTY). ([database.cc](https://raw.githubusercontent.com/NationalSecurityAgency/ghidra/master/Ghidra/Features/Decompiler/src/decompile/cpp/database.cc), [varmap.cc](https://raw.githubusercontent.com/NationalSecurityAgency/ghidra/master/Ghidra/Features/Decompiler/src/decompile/cpp/varmap.cc), [type.hh](https://raw.githubusercontent.com/NationalSecurityAgency/ghidra/master/Ghidra/Features/Decompiler/src/decompile/cpp/type.hh), [VarBERT](https://adamdoupe.com/publications/varbert-oakland2024.md))
- Ghidra structuring collapses the graph with rules in fixed order: goto, cat, proper-if, if-else, while-do, do-while, infinite loop, switch. If-no-exit and case fall-through run only when nothing else matches. When it is stuck, it marks one "likely goto" edge chosen by TraceDAG and BadEdgeScore. ([blockaction.cc](https://raw.githubusercontent.com/NationalSecurityAgency/ghidra/master/Ghidra/Features/Decompiler/src/decompile/cpp/blockaction.cc), [blockaction.hh](https://raw.githubusercontent.com/NationalSecurityAgency/ghidra/master/Ghidra/Features/Decompiler/src/decompile/cpp/blockaction.hh))
- Cifuentes (dcc) uses intervals and derived sequences for loops. A loop is while, repeat or endless by which of header and latch are conditional. The if follow node is the closest node with the if as idom and at least 2 in-edges. Four short-circuit patterns give compound conditions. Gotos appear only when no construct fits. ([Cifuentes 1993](https://www.cs.tufts.edu/~nr/cs257/archive/cristina-cifuentes/structuring-algorithm.pdf), [Cifuentes 1996](https://www.cs.tufts.edu/comp/150FP/archive/cristina-cifuentes/structuring-decompiled.pdf))
- Phoenix is semantics-preserving structural analysis in post-order. Acyclic schemas: Seq, IfThen, IfThenElse (needs inverse conditions), Switch. Loop refinement keeps the entrance with most in-edges and uses lexical loop membership (gotos cut 45%). Last resort removes one edge where neither end dominates the other. ([Phoenix paper](https://www.usenix.org/system/files/conference/usenixsecurity13/sec13-paper_schwartz.pdf), [Phoenix talk](https://www.usenix.org/conference/usenixsecurity13/technical-sessions/presentation/schwartz))

- DREAM is goto-free. It computes reaching conditions over graph slices, starts with one `if (cr)` per node, then refines to if/else, switch and cascades. Loops start as endless loops with breaks. Cost: 43,661 boolean expressions against 6,180 in source, and 104.3% more CFG edit distance than Hex-Rays. ([DREAM](https://www.ndss-symposium.org/wp-content/uploads/2017/09/11_4_2.pdf), [SAILR text](https://adamdoupe.com/publications/sailr-usenix2024.md))
- rev.ng "Comb" is goto-free through node duplication with "untangling" first. SAILR measured it at CFG edit distance 71.29 (+216.6% against Hex-Rays) and +116.3% calls. Duplication hurts faithfulness to the source. ([Comb paper](https://heaplab.deib.polimi.it/publication/11311-1147248/), [rev.ng slides](https://rev.ng/downloads/asiaccs-2020-presentation.pdf))

SAILR reverts them: duplicate merges, single-successor copies at goto targets, switch recovery and per-call-site noreturn. ([SAILR](https://www.usenix.org/conference/usenixsecurity24/presentation/basque), [SAILR text](https://adamdoupe.com/publications/sailr-usenix2024.md), [angr SAILR docs](https://docs.angr.io/en/latest/api/angr.analyses.decompiler.structuring.sailr.html))

#### Design implications

- The goal is few gotos and high faithfulness, not zero gotos. Never add boolean state variables. Duplicate only tiny blocks (about 3 statements or fewer) that end in return or a noreturn call.
- This report supersedes the decompiler research proposal for a separate small statement IR and lift-time flag fusion. Section 3.5 rules: the statement tree is an output view of L1, and fusion is a rewrite on the lazy thunk.
- Output is machine-addressable. Each statement has an address range in a separate `line_map: [{line, start, end}]`. Goto labels use addresses (`L_401234`). Variables have stable IDs such as `f@401130/v/stack:-0x14`, so renames and retypes survive a re-run.
- Report quality as data: `goto_count`, `label_count`, `max_nesting`, `stmt_count`, `unresolved_indirect_jumps`, `fallback_mode` (structured, partial, flat) and `warnings[]` with code, address and remedy, for example `W_JUMPTABLE_UNRESOLVED`.
- Passes are small, ordered and named. Each pass is pure (IR in, IR out) and can be switched off by name (deadcode, fold, structure, rename). Agents can ask for `--no-fold` or raw IR to test a claim.
- Every pass is deterministic: iterate in reverse post-order, sort ties by address, never use hash-map order.
- Inline string literals and resolve call names at print time from the symbol and PLT maps. These give the most agent value per line of code.
- Structurer (Phoenix-lite): post-order collapse with Seq, IfThen, IfThenElse (condition-aware), the 4 short-circuit shapes and Switch. Cyclic: While, DoWhile and endless loop with break/continue. Last resort virtualizes exactly one edge per step with a deterministic rule.
- SAILR-lite passes give the most goto reduction per line: return duplication, noreturn calls and stack-canary removal. Also loop-inversion cleanup (`if (c) do {B} while (c)` becomes `while (c) {B}`) and guard-clause flattening (no else after a then-branch that returns).
- Jump tables: match the PIC pattern and `jmp [T+idx*8]`, read N+1 entries (cap 1024) and build a Switch with merged case labels. When no pattern matches, emit `goto *(expr);` and a warning.
- Printer: precedence climbing with Ghidra's numbers. Negate conditions by flipping the compare operator. Use `for` only when init, condition and increment on one variable are adjacent. Add a cast only where widths differ.
- Goto fallback rules apply to secondary entries of irreducible loops and to the last-resort edge. They also apply to loop exits that are not break or continue. An unresolved indirect jump becomes a computed goto plus a warning. Duplication above the size limit also falls back to a goto. Over budget (about 500 nodes or the time limit), switch to FLAT mode: all blocks in address order with labels and gotos.
- Tool: `func_decompile(func_id, {max_nodes, max_ms, fold, view: c|ir|both})` returns `{id, signature, c, line_map, vars[], calls[], strings[], metrics, warnings[]}`. `symbol_rename` and `type_apply` change the project database and apply on the next decompile.
- Tests: a structurer trace-equivalence property test. Random CFGs (irreducible ones included) drive both the CFG walker and an AST interpreter with the same branch oracle. The block-visit traces must be equal. Every goto target label exists exactly once.
- Tests: golden fixtures at -O0/-O1/-O2 with key snippets (`while (`, `switch (`, `return puts("a");`, no `__stack_chk_fail`) and a goto budget per fixture. Recompile test: `gcc -fsyntax-only -w` with a small prelude. Leaf behavior test: compile the output and compare with the original on random inputs. Determinism: two runs give byte-identical JSON.

#### Pitfalls

- A switch can look like an if/else diamond, and the reverse. Match conditions as well as shape.
- Without the 4 short-circuit shapes, `&&` and `||` always give gotos. Match them before the if schemas.
- Do not fold a load past a store or call that may alias it. Do not fold a def out of a loop body.
- Flag details: `test r,r; jle` means `r <= 0`. `xor eax,eax` is a zero idiom, not a read. `ucomisd` uses CF, ZF and PF, and `jp` means unordered NaN.
- Missing noreturn data adds false edges and gotos. A tail call lifted as a plain jump merges two functions. Fix both before structuring.
- Greedy schemas (if-no-exit, case fall-through) applied early make better rules miss. Run them only when nothing else matches.
- Too much duplication shows code paths that do not exist in the source and costs tokens. Cap duplication to tiny exit blocks.
- Exact boolean simplification is NP-hard. Use only De Morgan, double negation, compare flips and constant folding.
- Every fixpoint loop (type propagation, rewrite rules) needs an iteration cap and a budget warning.
- Do not drop blocks silently. If structuring fails, give flat output, which is still correct, and report it.

### 3.8 Types, symbols, demangling and prototypes

#### Findings

- Ghidra `CParser` (JavaCC, 3,178 lines) needs input from `gcc -P -E`. It parses `__attribute__` but keeps only noreturn, and it ignores `_Alignas`. Errors are one string ("near token", file, line). Layout comes from a compiler-spec data organization plus bit-field packing flags. With a pack value, GCC bit-fields get alignment 1. ([C.jj](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Features/Base/src/main/javacc/ghidra/app/util/cparser/C/C.jj), [BitFieldPackingImpl](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/model/data/BitFieldPackingImpl.java), [AlignedComponentPacker](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/model/data/AlignedComponentPacker.java), [DataOrganizationImpl](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Framework/SoftwareModeling/src/main/java/ghidra/program/model/data/DataOrganizationImpl.java), [CParser API](https://ghidra.re/ghidra_docs/api/ghidra/app/util/cparser/C/CParser.html))
- radare2 parses types with a stripped TinyCC (LGPLv2) and a newer hand-written parser. Its sdb format is flat key=value: `func.strcpy.args=2`, `func.strcpy.arg.0=char *,dest`, `func.exit.noreturn=true`. `types.sdb.txt` has 586 functions. Calling conventions are data too (`cc.ms.arg0=rcx`). The data is LGPLv3, so use it as an oracle only. ([r2 C README](https://github.com/radareorg/radare2/blob/master/libr/anal/c/README.md), [r2 meson.build](https://github.com/radareorg/radare2/blob/master/libr/anal/meson.build), [r2 cparse.c](https://github.com/radareorg/radare2/blob/master/libr/anal/cparse.c), [types.sdb.txt](https://github.com/radareorg/radare2/blob/master/libr/anal/d/types.sdb.txt), [cc-x86-64.sdb.txt](https://github.com/radareorg/radare2/blob/master/libr/anal/d/cc-x86-64.sdb.txt), [r2 README](https://github.com/radareorg/radare2/blob/master/README.md), [r2 book types](https://book.rada.re/analysis/types.html))

Binary Ninja returns `TypeParserError{severity, message, file_name, line, column}` per issue, a good model for agent errors. ([angr sim_type.py](https://github.com/angr/angr/blob/master/angr/sim_type.py), [angr definitions](https://github.com/angr/angr/blob/master/angr/procedures/definitions/__init__.py), [parse_win32json.py](https://github.com/angr/angr/blob/master/angr/procedures/definitions/parse_win32json.py), [angr function.py](https://github.com/angr/angr/blob/master/angr/knowledge_plugins/functions/function.py), [angr definitions docs](https://docs.angr.io/en/latest/api/angr.procedures.definitions.html), [angr structured data](https://docs.angr.io/en/stable/advanced-topics/structured_data.html), [BN typeparser](https://api.binary.ninja/binaryninja.typeparser-module.html))

It supports `__attribute__` aligned/packed/mode, calling conventions, `__declspec` and `#pragma pack`. Its struct layout is about 70 lines, in bits, with overflow detection. ([lj_cparse.c](https://github.com/LuaJIT/LuaJIT/blob/v2.1/src/lj_cparse.c), [lj_cparse.h](https://github.com/LuaJIT/LuaJIT/blob/v2.1/src/lj_cparse.h))
- SysV x86-64 psABI: a struct takes the alignment of its most aligned member, and its size is a multiple of that alignment. Bit-fields go right to left and must fit a storage unit of their declared type. Unnamed bit-fields do not change struct alignment. `_Bool` is 1/1, `__int128` 16/16, `long double` 16/16. Measured: GCC makes plain `int` bit-fields signed. ([x86-64 psABI](https://gitlab.com/x86-psABIs/x86-64-ABI/-/blob/master/x86-64-ABI/low-level-sys-info.tex))
- clang's Itanium layout adds rules not in the psABI text. Under `#pragma pack`, bit-fields get no padding and can straddle units. The pack value caps an aligned attribute. A packed bit-field always takes the next free bit. ([RecordLayoutBuilder.cpp](https://github.com/llvm/llvm-project/blob/main/clang/lib/AST/RecordLayoutBuilder.cpp))
- Measured i386 SysV vs MSVC x86: on i386 SysV, `double` and `long long` align to 4 in structs, and `long double` is 12/4. The same struct is 36 bytes on i386 SysV, 48 on MSVC x86 and 48 on x86-64. MSVC x64 is LLP64: `long` is 4, `long double` is 8/8, and enums are always 4 bytes. ([MS x64 conventions](https://learn.microsoft.com/en-us/cpp/build/x64-software-conventions), [i386 psABI](https://gitlab.com/x86-psABIs/i386-ABI))
- MSVC rule: a bit-field joins the unit only if the last field was a non-zero bit-field of the same type size and the width fits. Otherwise it starts a new unit of `sizeof(type)`. Fields never straddle units. A zero-width field counts only after a non-zero bit-field. `__declspec(align)` ignores `#pragma pack`: under pack(1), `{char c; int x aligned(8);}` is 5 bytes on SysV and 16 on MSVC (measured). ([MS C bit fields](https://learn.microsoft.com/en-us/cpp/c-language/c-bit-fields), [RecordLayoutBuilder.cpp](https://github.com/llvm/llvm-project/blob/main/clang/lib/AST/RecordLayoutBuilder.cpp))
- AAPCS64 bit-fields: with container width C and alignment A, `UCB = C - (BA % A)` and `NCBA = TRUNCATE(BA + A - 1, A)`. For width W: if W==0 or W > UCB, move to NCBA; place the field; add W. The container type adds alignment also for unnamed and zero-width fields. So `{char a; int :0; char b;}` is 8 bytes on AArch64, 5 on x86-64 and 2 on MSVC (measured). Plain char is unsigned. ([AAPCS64](https://github.com/ARM-software/abi-aa/blob/main/aapcs64/aapcs64.rst))
- Measured layout edge cases (gcc and clang agree on 36 x86-64 and i386 probes): packed struct plus aligned(4) member gives offset 4, size 8. `{char c; int a[];}` is size 4, align 4. An empty struct is 0 in GNU C and 4 in clang MS mode. Under pack(2), `{char; double; int c:7}` is 12 on SysV and 14 on MSVC. `enum {A=0x100000000}` is 8 on GNU and 4 on MSVC.
- `clang -target T -S -emit-llvm -o /dev/null -Xclang -fdump-record-layouts` prints `byteoff[:bitlo-bithi] | type name` and `[sizeof=N, align=M]`. It needs codegen, because `-fsyntax-only` dumps only used records. 500 random structs dump in about 60 ms per target (measured).

#### Design implications

- Core types: `TypeId(u32)` inside one database, `t:<fnv64 of canonical C text>` outside. `Type{Prim, Ptr, Array, Record, Enum, Typedef, Func, Qual}`. `Record{kind, name, fields, attrs{packed, aligned, pack, ms_align}, complete}`. `Field{name, ty, bits, align_attr, packed}`. `Sig{ret, params, variadic, cc, noreturn, fmt, nonnull, asm_name}`.
- Layout is a function of (record, `DataModel`), never stored truth. `DataModel` holds (size, abi_align) per scalar, `char_signed`, bit-field rule (SysV or MS), `unnamed_bf_affects_align`, enum rule and empty-struct size. Presets: x86_64-sysv, i386-sysv (double 8/4, long double 12/4), x86_64-msvc, i386-msvc, aarch64-aapcs and riscv64.
- SysV layout works in bits with checked u64. Bit-field alignment is 1 when packed, else the type alignment, raised by an aligned attribute and capped by pack. Without pack, a field that would straddle its unit moves to the next aligned unit. A zero-width field aligns to its type. Unnamed fields add alignment only when the data model says so.
- MSVC layout follows clang's Microsoft builder: track the unit size of the last bit-field and the bits left. Join the unit only for the same type size and enough bits. A zero-width field after no bit-field is ignored. `ms_align` is immune to pack. Unions ignore bit-field alignment. AAPCS64 uses the CBA/UCB/NCBA rules.
- One parser, three modes from LuaJIT: `decls` (struct, union, enum, typedef, prototypes), `type` (abstract declarator) and `sig` (one prototype). A built-in prelude gives stdint, size_t and Win32 names (BYTE, DWORD, HANDLE, LPCSTR). Unknown `__attribute__` entries are warnings.
- Error shape: `{"ok":false, "errors":[{"code":"E_UNKNOWN_TYPE", "sev":"error", "msg":..., "at":{"line","col","byte","len"}, "snippet":..., "expected":[...], "did_you_mean":["HANDLE"], "fix":...}]}`. A batch is atomic. Codes: `E_SYNTAX E_UNKNOWN_TYPE E_REDEF_CONFLICT E_INCOMPLETE_BY_VALUE E_BITFIELD_WIDTH E_CONST_EXPR E_OVERFLOW E_LIMIT E_UNSUPPORTED`, warnings `W_ATTR_IGNORED W_TAG_AS_TYPEDEF`.
- Parser limits: input 1 MiB, 200k tokens, identifier 1024 bytes, nesting 64, record nesting 32, 4096 fields, 65,536 enumerators, pack stack 16. All size arithmetic uses checked u64. Constants evaluate in i128 with checked ops. Type graphs get cycle tests. Recursion is depth-counted.
- Demangler API returns structure: `Demangled{scheme, path, name, params, ret, cc, method{cv, ref_q, is_static: Tri, is_virtual: Tri, access}, template_args, suffix, text}`. Itanium `is_static` is always Unknown. MSVC sets it.
- Demangler limits: input 4 KiB, depth 256, 65,536 AST nodes in a `Vec` arena and output 64 KiB with a `{size limit}` marker. Backrefs point strictly backwards. Each node has a print guard. MSVC backref tables hold 10 entries. A failure returns `{code: E_DEMANGLE, at, reason}`.
- Signature mapping: namespaces come from the path. For Itanium, add `this` only by heuristic and mark it `confidence: heuristic`. Leave Itanium return types unknown. MSVC gives full signatures (`confidence: mangled`). Rust gives names only. Source rank: User > Dwarf > Pdb > Mangled > ProtoDb > Analysis > Default.
- Prototype database: an embedded binary format made offline and committed. The header has `GTPD`, a version and a data-model tag. Then come a sorted string table (LEB128), a type table and a symbol index. The index holds name, signature, library, noreturn, SetLastError and asm alias. Make one database per data model. Estimates: glibc 40-60 KB, Windows core 150-250 KB.
- Prototype tiers: Tier 0 is about 150 hand-curated functions with noreturn and format flags. Tier 1 is generated from local glibc headers. Tier 2 is the WinAPI core from win32json (keep the MIT attribution). Tier 3 is user import. Do not parse `.gdt` in the MVP.
- Tools: `type_declare{c, abi}`, `type_layout{type, abi|abis}` with lines like `+0x10.4 b3 unsigned short:9`, `type_layout_diff{type, abis}`, `func_set_signature{func, c}`, `proto_lookup{name, lib?}` and `symbol_demangle{syms[], scheme, verbose}` with short LLVM style by default.
- Tests: a layout differential with 10k random records per target per CI run (about 1.2 s per target) against clang `-fdump-record-layouts` and gcc. Shrink each mismatch and keep it as a regression case. The 36 measured edge cases are golden unit tests.
- Tests: the parser must parse all `gcc -E -P` output of the 52 glibc headers with zero errors and match all 2,787 aux-info prototypes. A token-mutation fuzzer and bombs (`(` × 100000, `*` × 1000000, huge arrays, typedef cycles) run in a 256 KiB thread stack.
- Tests: Itanium against the 29,931 LLVM pairs (target ≥ 99%) and the 146,199 local symbols. MSVC against llvm-undname on clang `-target *-pc-windows-msvc` fixtures. Rust against local rlib symbols and the rustc-demangle regression vectors. DoS inputs run with a 64 KiB stack.

#### Pitfalls

- The psABI text says plain `int` bit-fields are unsigned, but GCC and MSVC make them signed. Follow the compiler. AArch64 and RISC-V plain char is unsigned.
- Under `#pragma pack`, GCC and clang add no padding before bit-fields. The aligned attribute is capped on SysV but not in MSVC mode.
- Unnamed and zero-width bit-fields differ per ABI. The same 3-member struct is 5, 8 or 2 bytes.
- On i386, `__alignof__(double)` is 8 (preferred) but the in-struct alignment is 4. The preferred value gives wrong offsets.
- MSVC enums are always 4 bytes and truncate 64-bit enumerators. GNU widens to 8 or shrinks packed enums to 1.
- Do not copy Ghidra's size-to-alignment map or its attribute shortcuts. They cannot show per-type ABI differences.
- clang's MS layout only approximates MSVC (empty C struct 4, real MSVC rejects it). Mark such cases as "unverified".
- glibc redirects symbols with `__asm__` (`__isoc23_scanf`, LFS `*64`, `*_chk`). Index prototypes by the linked symbol name.
- Header prototypes differ by target and glibc version (`struct stat`, `off_t`, `time_t`). One database for all ABIs corrupts layouts.
- c++filt and llvm-cxxfilt differ in style on 1.9% of symbols. Compare with normalization and accept either oracle.
- Do not invent `int` returns or always add `this` for Itanium names. Both corrupt decompiler output.
- Deep `P` chains, nested templates and backref loops overflow the stack. Backref explosions give 2^n output. Every recursive path needs a depth counter, and printing needs an output cap.
- Do not demangle to text and parse the text again. Keep the AST.
- libc.a signatures match only the same glibc build. Linker relaxation changes 1-3 bytes near GOTPCRELX and TLS relocations.
- Licenses: radare2 sdb data is LGPLv3, glibc header text is LGPL, SDK header licenses still apply to win32metadata. Ghidra lists and LLVM test corpora are Apache-2.0 with attribution.

### 3.9 Agent protocol: MCP, JSON-RPC, JSON and CLI

#### Findings

- MCP revision 2026-07-28 is released and makes MCP stateless. It removes `initialize`, `notifications/initialized`, `ping` and `logging/setLevel`. Each request carries `_meta` keys `io.modelcontextprotocol/protocolVersion` and `clientCapabilities`. A missing key gives -32602. Servers must implement `server/discover`. A version mismatch gives -32022 with `{supported, requested}`. ([2026-07-28 changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog), [2026-07-28 lifecycle](https://modelcontextprotocol.io/specification/2026-07-28/basic/lifecycle), [server/discover](https://modelcontextprotocol.io/specification/2026-07-28/server/discover))
- Every 2026-07-28 result needs `resultType` (`complete` or `input_required`). A "dual-era" server can serve both modes. An `initialize` request selects legacy semantics for the stdio process. A request with modern `_meta` gets a stateless answer. A dual-era client probes with `server/discover` first. ([2026-07-28 lifecycle](https://modelcontextprotocol.io/specification/2026-07-28/basic/lifecycle), [2026-07-28 stdio](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/stdio))
- stdio framing is the same in 2025-11-25 and 2026-07-28. Each line holds one UTF-8 JSON-RPC message with no embedded newline. stdout carries only MCP messages, and logs go to stderr. The client closes stdin, then sends SIGTERM, then SIGKILL. A stdio process is not a session, so state across requests needs explicit IDs. ([2025-11-25 transports](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports), [2026-07-28 base](https://modelcontextprotocol.io/specification/2026-07-28/basic))
- Legacy lifecycle: `initialize {protocolVersion, capabilities, clientInfo}` gets `{protocolVersion, capabilities, serverInfo, instructions}`. The server echoes a supported version, else it returns its latest. The client then sends `notifications/initialized`. Server capabilities: prompts, resources, tools (each with `listChanged`), logging, completions, tasks. ([2025-11-25 lifecycle](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle), [schema.ts 2025-11-25](https://raw.githubusercontent.com/modelcontextprotocol/modelcontextprotocol/main/schema/2025-11-25/schema.ts))
- Message rules: an MCP request ID is a string or integer, never null. The receiver never answers a notification. An error response has a null ID only when the ID could not be read. 2025-06-18 removed JSON-RPC batch arrays. If a server accepts arrays, an all-notification batch gets no response. ([2025-11-25 base](https://modelcontextprotocol.io/specification/2025-11-25/basic), [2025-06-18 changelog](https://modelcontextprotocol.io/specification/2025-06-18/changelog), [JSON-RPC 2.0](https://www.jsonrpc.org/specification))
- Error codes: -32700 parse error, -32600 invalid request, -32601 method not found, -32602 invalid params, -32603 internal error. 2026-07-28 reserves -32020 to -32099 for MCP (-32020 HeaderMismatch, -32021 MissingRequiredClientCapability, -32022 UnsupportedProtocolVersion). Application codes stay outside -32768 to -32000. A bad cursor gets -32602. ([JSON-RPC 2.0](https://www.jsonrpc.org/specification), [2026-07-28 base](https://modelcontextprotocol.io/specification/2026-07-28/basic), [2025-11-25 resources](https://modelcontextprotocol.io/specification/2025-11-25/server/resources))
- A tool has name, title, description, `inputSchema` (type object), `outputSchema`, annotations, icons, `execution.taskSupport` and `_meta`. A tool without parameters uses `{"type":"object","additionalProperties":false}`. The default dialect is JSON Schema 2020-12. Recommended names have 1-128 characters from `[A-Za-z0-9_.-]`. 2026-07-28 asks for a deterministic `tools/list` order. ([2025-11-25 tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools), [2026-07-28 tools](https://modelcontextprotocol.io/specification/2026-07-28/server/tools))
- Annotation defaults: `readOnlyHint` false, `destructiveHint` true, `idempotentHint` false, `openWorldHint` true. An omitted field therefore reads as "destructive and open-world". Clients treat annotations as untrusted. ([schema.ts 2025-11-25](https://raw.githubusercontent.com/modelcontextprotocol/modelcontextprotocol/main/schema/2025-11-25/schema.ts), [schema.ts 2025-06-18](https://raw.githubusercontent.com/modelcontextprotocol/modelcontextprotocol/main/schema/2025-06-18/schema.ts))
- `tools/call` returns `{content[], structuredContent?, isError?}`. In 2025-11-25, `structuredContent` must be an object. The spec recommends that a tool with structured output also returns the JSON as a text block. The TypeScript SDK client throws when a tool has an `outputSchema` but returns no `structuredContent` and no `isError`. ([2025-11-25 tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools), [TS SDK client.ts](https://raw.githubusercontent.com/modelcontextprotocol/typescript-sdk/main/packages/client/src/client/client.ts))
- An unknown tool or a malformed call is a JSON-RPC error (-32602). Input validation and business failures must be `isError:true` results with actionable text (SEP-1303), because the model sees these. Claude Code cuts error text above about 11,000 characters to its first and last 5,000. ([2025-11-25 changelog](https://modelcontextprotocol.io/specification/2025-11-25/changelog), [Claude Code MCP](https://code.claude.com/docs/en/mcp))
- Claude host limits: the Claude API tool name regex is `^[a-zA-Z0-9_-]{1,128}$` (no dots). Root `anyOf`/`oneOf`/`allOf` is rejected. Claude Code names tools `mcp__<server>__<tool>` and cuts instructions and descriptions at 4,096 characters. It warns at 10,000 output tokens and caps at 25,000. It saves text above 50,000 characters to a file. ([Claude API define tools](https://platform.claude.com/docs/en/agents-and-tools/tool-use/define-tools), [Claude Code MCP](https://code.claude.com/docs/en/mcp))
- Pagination: the cursor is opaque, and the server sets the page size. `nextCursor` exists only when more results exist. Clients must not parse or keep cursors. MCP does not paginate inside tool results, so tools use the same pattern through arguments. ([pagination](https://modelcontextprotocol.io/specification/2025-11-25/server/utilities/pagination))
- Resources: `resources/list`, `resources/read`, RFC 6570 templates, subscriptions and list-change notifications. Prompts: `prompts/list` and `prompts/get`. Claude Code offers resources as @-mentions and prompts as slash commands. ida-pro-mcp uses read-only resources such as `ida://xrefs/from/{addr}`. ([2025-11-25 resources](https://modelcontextprotocol.io/specification/2025-11-25/server/resources), [2025-11-25 prompts](https://modelcontextprotocol.io/specification/2025-11-25/server/prompts))
- Cancellation is `notifications/cancelled {requestId, reason}`. The receiver stops the work and sends no response. Progress needs `_meta.progressToken`. Then `notifications/progress {progressToken, progress, total, message}` must increase and stop at completion. ([cancellation](https://modelcontextprotocol.io/specification/2025-11-25/basic/utilities/cancellation), [progress](https://modelcontextprotocol.io/specification/2025-11-25/basic/utilities/progress))
- MCP tasks were experimental in 2025-11-25 and moved to a redesigned extension in 2026-07-28. Do not depend on them. Return a server job handle and a poll tool. ([tasks](https://modelcontextprotocol.io/specification/2025-11-25/basic/utilities/tasks))
- Server instructions give cross-tool relations, workflows and global limits. They do not repeat tool descriptions. One workflow instruction raised multi-step success from 60% to 85%. ([server instructions](https://blog.modelcontextprotocol.io/posts/2025-11-03-using-server-instructions/))
- Stateful handles (2026-07-28 guidance): a creation tool returns a handle in `structuredContent`, and later calls pass it as an argument. An unknown or expired handle gives an `isError` result that says so. Ghidra has `getExecutableSHA256()` and `getUniqueProgramID()` for persistent references. ([2026-07-28 tools](https://modelcontextprotocol.io/specification/2026-07-28/server/tools), [Ghidra Program API](https://ghidra.re/ghidra_docs/api/ghidra/program/model/listing/Program.html))
- Ghidra edits: `startTransaction(desc)` returns an ID, a second call opens a sub-transaction, and `endTransaction(id, false)` rolls back. Each top-level transaction is one named undo unit with `undo`, `redo` and `getAllUndoNames`. ([Ghidra DomainObject API](https://ghidra.re/ghidra_docs/api/ghidra/framework/model/DomainObject.html))
- GhidraMCP shows tool sprawl, for example `rename_function` next to `rename_function_by_address`. ida-pro-mcp avoids it with batch-first tools that take one item or a list. ([GhidraMCP server.py](https://raw.githubusercontent.com/LaurieWired/GhidraMCP/master/src/ghidra_mcp/server.py), [ida-pro-mcp](https://github.com/mrexodia/ida-pro-mcp))
- RFC 8259: only 4 whitespace characters. No NaN, Infinity or leading zeros. Interoperable integers are within ±(2^53-1). Strings must escape `"`, `\` and U+0000-U+001F. Non-BMP characters use surrogate pairs. A lone surrogate is grammatical but I-JSON forbids it. Parsers may limit size and depth. JSONTestSuite (MIT) has y_, n_ and i_ files. ([RFC 8259](https://www.rfc-editor.org/rfc/rfc8259), [RFC 7493](https://www.rfc-editor.org/rfc/rfc7493), [JSONTestSuite](https://github.com/nst/JSONTestSuite))
- Measured: `0xffffffff81000123` comes back from Node `JSON.parse` as `...000`, and Python `float()` loses the low bits. RFC 7493 and RFC 8785 recommend strings for such values. ([RFC 7493](https://www.rfc-editor.org/rfc/rfc7493), [RFC 8785](https://www.rfc-editor.org/rfc/rfc8785))
- Measured Rust std traps (rustc 1.97): `str::parse::<f64>` accepts `.5`, `5.`, `+1`, `inf`, `NaN` and `01`. `Display` for f64 prints 1e21 as 22 digits and NaN as `NaN`; `{:?}` gives shortest round-trip text. `u64::from_str_radix` rejects a `0x` prefix. `HashMap` iteration order is random. `println!` panics on a broken pipe. ([HashMap docs](https://doc.rust-lang.org/std/collections/struct.HashMap.html), [println and closed stdout](https://internals.rust-lang.org/t/defusing-println-when-stdout-is-closed/20325), [broken pipe test](https://rust.googlesource.com/rust-lang/rust/+/HEAD/tests/ui/process/println-with-broken-pipe.rs))
- RFC 8785 (JCS) sorts keys by UTF-16 code units, uses no whitespace and fixed escapes. It is a good canonical mode for content hashes and golden tests. ([RFC 8785](https://www.rfc-editor.org/rfc/rfc8785))
- During 2026, Claude Code reports show array and object arguments that arrive as JSON-encoded strings. A documented server fix parses such a string before schema validation when the schema wants an array or object. ([issue 22394](https://claudeissues.com/issue/22394-mcp-tools-array-parameters-serialized-as-strings-instead-of-arrays), [issue 59227](https://claudeissues.com/issue/59227-mcp-tool-calls-list-dict-arguments-sent-as-json-encoded-strings-instead-of-nativ), [issue 73137](https://claudeissues.com/issue/73137-mcp-tool-calls-with-array-typed-parameters-list-int-arrive-server-side-as-string), [STAC MCP fix](https://glama.ai/mcp/servers/@BnJam/stac-mcp/blob/d230f1690e1bd24827d8895823b1efb1f27e07cc/docs/MCP_PARAMETER_FIX.md))
- CLI rules for machine callers: data on stdout, messages on stderr, `--json` and distinct exit codes. Do not prompt without a TTY. Offer `--dry-run`, validate before side effects and change interfaces only by addition. sysexits codes (64 USAGE, 65 DATAERR, 66 NOINPUT, 70 SOFTWARE, 74 IOERR) are deprecated but usable. `rename(2)` is atomic on one filesystem and fails with EXDEV across filesystems. ([clig.dev](https://clig.dev/), [sysexits](https://man.freebsd.org/cgi/man.cgi?query=sysexits), [rename(2)](https://man7.org/linux/man-pages/man2/rename.2.html))
- `_meta` keys use a reverse-DNS prefix. Prefixes with `modelcontextprotocol` or `mcp` as second label are reserved, so vendor keys use `dev.ghidorah/`. `progressToken` and OpenTelemetry keys are reserved. ([2025-11-25 base](https://modelcontextprotocol.io/specification/2025-11-25/basic))

#### Design implications

- One registry of plain Rust data generates `ghidorah mcp`, `ghidorah call <tool> <json|@file|->`, `ghidorah batch` (JSONL in and out) and `ghidorah tools --json` (the same objects as `tools/list`).
- Dual-era server: answer `initialize` with supported versions `2025-11-25`, `2025-06-18` and `2025-03-26`. Serve modern `_meta` requests and `server/discover` for `2026-07-28`. Add `resultType:"complete"` to every result; legacy clients ignore unknown fields.
- Tool names match `^[a-z][a-z0-9_]{0,40}$`, for example `func_list`, `func_get`, `xref_list`, `string_search`, `mem_read`, `symbol_rename`, `comment_set`, `edit_batch`, `history_undo`, `binary_load`, `analysis_start`, `job_status`. The search keywords go in the first sentence of each description.
- Use about 15-25 merged tools. `func_get` takes `include: [disasm, decomp, xrefs, strings, callers, callees]` and `response_format: concise|detailed`. Tools accept one item or a list and return per-item errors.
- Results: `structuredContent` is always an object (wrap lists as `{items, total, next_cursor, truncated}`) plus one text block with the same compact JSON. Declare `outputSchema` only for tools with a stable shape.
- Two error tiers. JSON-RPC errors only for protocol faults. Model-fixable failures are `isError:true` with `{error:{code, message, hint, valid_example, retryable}}`, stable UPPER_SNAKE codes and a hint that names the next tool or argument.
- Set all four annotation hints on every tool. Read tools: `readOnlyHint:true, openWorldHint:false`. Additive edits: `destructiveHint:false, idempotentHint:true`. Patches and deletes: `destructiveHint:true`. Vendor fields use `_meta` keys with prefix `dev.ghidorah/`.
- Token budget: each tool has a default limit (for example 100 rows or 200 instructions) and a hard cap below about 40,000 characters. A cut result has `truncated:true`, `total`, `next_cursor` and a hint. The opaque cursor holds offset plus revision, and a stale cursor fails clearly.
- Edits: each mutating call is one named transaction. `edit_batch` is all-or-nothing and returns `{rev, txn_id, applied}`. It supports `dry_run` (returns the diff) and `expected_rev` (a mismatch gives `CONFLICT` and the current revision). `history_list`, `history_undo` and `history_redo` expose the stack.
- Project directory: `project.json` manifest, `bin/<sha256>` immutable inputs, `journal.jsonl` append-only transactions and `snapshot.json` written by temp file, fsync and rename. Open loads the snapshot and replays the journal tail.
- Concurrency with std only: one reader thread splits stdin on `\n`, removes a trailing `\r` and limits line size (for example 16 MiB). A mutex-guarded writer writes and flushes each line. Each request has an `Arc<AtomicBool>` cancel flag. Progress notifications are rate-limited.
- Coerce leniently before validation: a string that parses as the expected array or object, numeric strings for integers and every documented address form. Report coercions in detailed mode only.
- Server instructions (2,000 characters or fewer) give the workflow `binary_load → analysis_start/job_status → func_list → func_get`, the address format, handle lifetimes, undo rules and limits. A `tool_search` tool returns names, then summaries, then full schemas.
- JSON module (about 600-900 lines): `Value{Null, Bool, Number(raw lexeme), String, Array, Object(Vec<(String, Value)>)}` keeps insertion order. Use a strict RFC 8259 lexer with a depth limit of 128 and a byte limit. Join surrogate pairs and reject lone surrogates with a byte offset. Write f64 with `{:?}` after `is_finite`. Offer an optional JCS mode.
- CLI exit codes: 0 success, 1 tool error (`isError`), 2 usage or protocol error. Also `--version`, `--help`, `NO_COLOR`, never a prompt. stdout `BrokenPipe` is a clean exit. A panic hook writes to stderr only.
- Tests: vendored JSONTestSuite files (y_ must parse, n_ must fail, i_ pinned). Differential round trip with `python3 -I` (with `parse_constant` that rejects NaN). Golden protocol transcripts: spawn `ghidorah mcp`, feed JSONL, compare byte for byte.
- Tests: a schema self-test for every tool. It tests the object schema, no root combinators, the name regex, full name ≤ 128, description ≤ 4,096, all four hints and valid examples. Token-budget tests on large fixtures. Coercion tests. Determinism across two processes (`GHIDORAH_FIXED_TIME` pins times).

#### Pitfalls

- A server built only for `initialize` fails with 2026-07-28 clients. A server built only for the stateless era fails with legacy clients. Build dual-era.
- MCP allows dots in tool names, but the Claude API rejects them. Full names above 128 characters are dropped without notice.
- An f64 NaN or inf prints as `NaN`/`inf`, which is invalid JSON and breaks the client parser.
- Do not trust `str::parse` for JSON numbers. Validate the grammar first and keep the raw lexeme.
- A recursive parser without a depth limit overflows the stack on 100,000 nested arrays, mostly on spawned threads.
- A Rust `String` cannot hold a lone surrogate. Choose a policy (reject or U+FFFD), document it and test it.
- Strings from binaries are often not UTF-8. Return a lossy `text` field and an exact `hex` field together.
- Any `HashMap` order on an output or cursor path makes responses differ between runs and breaks prompt caching.
- Anything on stdout that is not an MCP message corrupts the stream. Handle EPIPE so the process does not panic.
- Validation failures sent as -32602 are often hidden from the model. Only an unknown tool or a bad request shape is a protocol error.
- Do not declare `outputSchema` and then return a non-error result without `structuredContent`. Do not make a list the root of `structuredContent`.
- Unset annotations read as destructive and open-world. Hosts can then ask for extra confirmation or block calls.
- Do not answer notifications. Do not send a response after a cancellation. Do not keep cursors after edits.
- Do not build on MCP tasks or `resources/subscribe`; both changed in 2026-07-28.
- Do not treat the stdio process as the session. Claude Code can restart servers. Persist state and use explicit handles.
- A plain overwrite of a project file corrupts data on a crash. Put the temp file in the same directory, because `rename` across filesystems fails.

#### Findings

- Verus is not installable as a crate. `verus` and `cargo-verus` on crates.io are empty placeholders. `vstd` needs `verus_builtin_macros`, which depends on proc-macro2, quote and syn, so a Cargo dependency on `vstd` breaks the zero-dependency rule. Official binaries are GitHub release zips. ([Verus INSTALL.md](https://github.com/verus-lang/verus/blob/main/INSTALL.md), [vstd on crates.io](https://crates.io/crates/vstd), [cargo verus guide](https://verus-lang.github.io/verus/guide/cargo_verus.html))
- Verus main (commit ffc9d20, 2026-10-16) pins toolchain 1.98.1 with `rustc-dev` and `llvm-tools`, and Z3 4.16.0. INSTALL.md still shows an old example toolchain (1.86.0). ([rust-toolchain.toml](https://github.com/verus-lang/verus/blob/main/rust-toolchain.toml), [get-z3.sh](https://github.com/verus-lang/verus/blob/main/source/tools/get-z3.sh))

([Verus BUILD.md](https://github.com/verus-lang/verus/blob/main/BUILD.md), [z3-solver 4.16.0.0](https://pypi.org/project/z3-solver/4.16.0.0/))
- Verus syntax: inside `verus! { }`, functions are exec (default, compiled), `proof fn` (erased) or `spec fn` (erased, no requires/ensures). Return values are named: `fn f(x: u32) -> (r: u32) requires .. ensures ..`. A pub spec fn is `open` or `closed`. Loops and recursion need `decreases`. `int` and `nat` are ghost-only types, and spec arithmetic does not overflow. ([syntax.rs](https://github.com/verus-lang/verus/blob/main/examples/syntax.rs), [getting started](https://verus-lang.github.io/verus/guide/getting_started_cmd_line.html), [integers](https://verus-lang.github.io/verus/guide/integers.html))
- Ghost state: `let ghost u: int = ..` changes only inside `proof { }`. Struct fields use `Ghost<T>` and `Tracked<T>`, read with `x@`. A ghost history is a field such as `hist: Ghost<Seq<Seq<u8>>>`. ([var modes](https://verus-lang.github.io/verus/guide/reference-var-modes.html), [syntax.rs](https://github.com/verus-lang/verus/blob/main/examples/syntax.rs))
- The `&mut` spec syntax changed in 2026. A postcondition must use `*old(x)` or `*final(x)`, for example `ensures final(self)@ == old(self)@.insert(k, v)`. Measured: the old form `ensures *x == *old(x) + 1` now fails. Most online examples and model training data show the old form. ([mutable references](https://verus-lang.github.io/verus/guide/mutable-references.html), [vstd vec.rs](https://github.com/verus-lang/verus/blob/main/source/vstd/std_specs/vec.rs))
- The View pattern: `impl View for T { type V = Map<u64, V>; open spec fn view(&self) -> .. }`, and `e@` means `e.view()`. `#[verifier::type_invariant]` with `use_type_invariant(&*self)` removes `requires wf()` from pub methods. ([view.rs](https://github.com/verus-lang/verus/blob/main/source/vstd/view.rs), [BST type invariant](https://github.com/verus-lang/verus/blob/main/examples/guide/bst_map_type_invariant.rs), [at-sign](https://verus-lang.github.io/verus/guide/reference-at-sign.html))
- vstd collections: `Seq`, `Set` and `Map` are finite. `ISet` and `IMap` can be infinite. Assert sequence equality with `=~=`. `v[i] = x` on a Vec is not supported, so use `v.set(i, x)`. Slice ranges `&buf[a..b]` are supported. `checked_add` has the spec `if x + y > MAX { None } else { Some(..) }`. ([spec libraries](https://verus-lang.github.io/verus/guide/spec_lib.html), [lib_examples.rs](https://github.com/verus-lang/verus/blob/main/examples/guide/lib_examples.rs), [vstd slice.rs](https://github.com/verus-lang/verus/blob/main/source/vstd/std_specs/slice.rs), [pervasive.rs](https://github.com/verus-lang/verus/blob/main/source/vstd/pervasive.rs), [vstd num.rs](https://github.com/verus-lang/verus/blob/main/source/vstd/std_specs/num.rs))
- Measured, verified in about 1 s each: (1) a bounded `Reader` with `wf: pos <= buf.len()` and `read_u32_le`, `read_u8` and `take(n)`. (2) Checked u64 range math (`range_end`, `offset_in`). A negative test (`< 3` in place of `< 4`) fails with "index in bounds". ([overflow guide](https://verus-lang.github.io/verus/guide/overflow.html), [overflow example](https://github.com/verus-lang/verus/blob/main/examples/guide/overflow.rs))
- Measured, verified: (3) a sorted non-overlapping interval map with a pairwise `i < j` invariant, binary-search `find` and `insert`. (4) An undo log of `(offset, old byte)` records with a ghost history. Its `undo()` restores `hist.last()`. Removing a neighbour test gives "assertion failed". ([multiple triggers](https://verus-lang.github.io/verus/guide/multitriggers.html), [binary search](https://verus-lang.github.io/verus/guide/binary_search.html), [refinement.rs](https://github.com/verus-lang/verus/blob/main/examples/state_machines/refinement.rs), [adder_with_max.rs](https://github.com/verus-lang/verus/blob/main/examples/state_machines/adder_with_max.rs), [extensional equality](https://verus-lang.github.io/verus/guide/extensional_equality.html))
- Verus proof rules: nonlinear arithmetic needs `by(nonlinear_arith)`. Bit operations and `as` truncation need `by(bit_vector)`. Every exec `+ - *` needs an overflow proof. Adjacent-element quantifiers make matching loops. A loop sees only what its invariant restates. `--no-cheating` rejects `assume` and `external_body`. A pub open spec fn cannot read private fields. ([nonlinear](https://verus-lang.github.io/verus/guide/nonlinear.html), [bit_vector](https://verus-lang.github.io/verus/guide/reference-prover-mode-bit-vector.html), [as-casts](https://verus-lang.github.io/verus/guide/reference-as.html), [loops](https://verus-lang.github.io/verus/guide/while.html), [termination](https://verus-lang.github.io/verus/guide/exec_termination.html), [checklist](https://verus-lang.github.io/verus/guide/checklist.html))

Free functions use `#[cfg_attr(verus_only, verus_spec(..))]`. Methods need a real `#[verus_verify]` on struct and impl, from a std-only proc-macro stub crate that returns its input unchanged. ([exec attributes](https://verus-lang.github.io/verus/guide/exec_attr.html), [erasure](https://verus-lang.github.io/verus/guide/erasure.html), [driver.rs](https://github.com/verus-lang/verus/blob/main/source/rust_verify/src/driver.rs), [syntax_attr.rs](https://github.com/verus-lang/verus/blob/main/examples/syntax_attr.rs))

Other flags: `--no-cheating`, `--rlimit`, `--verify-module`, `--verify-function`, `--expand-errors`, `--triggers-mode silent`. ([config.rs](https://github.com/verus-lang/verus/blob/main/source/rust_verify/src/config.rs))

Merge with `llvm-profdata merge -sparse`. List test objects with `cargo test --no-run --message-format=json`. Report with `llvm-cov report` or `export --summary-only` (JSON totals). ([instrument-coverage](https://doc.rust-lang.org/rustc/instrument-coverage.html))
- Measured coverage limits on stable 1.97: `#[coverage(off)]` is unstable. Branch and MC/DC coverage are nightly-only. Doctest coverage is nightly-only. Function names are v0-mangled with no demangler shipped. A CLI binary run as a subprocess writes its own profile and needs its own `--object`. ([coverage options](https://doc.rust-lang.org/unstable-book/compiler-flags/coverage-options.html))

([Cargo lints](https://doc.rust-lang.org/cargo/reference/manifest.html#the-lints-section), [workspace lints](https://doc.rust-lang.org/cargo/reference/workspaces.html#the-lints-table), [clippy usage](https://doc.rust-lang.org/clippy/usage.html), [lint_groups_priority](https://rust-lang.github.io/rust-clippy/master/index.html#lint_groups_priority))

Why. Action.". Use one verb per action in the whole project. A heuristic checker can test length, passive voice, present perfect and a ban list (ste-eval weights: length 4, passive 3). #### Design implications

- Keep Verus outside the Cargo graph. Use the hybrid pattern: specs in `#[verus_spec]`/`#[verus_verify]`, a std-only stub proc-macro crate (for example `ghidorah-spec`), and `#[cfg(verus_only)]` only on `use vstd::prelude::*` and spec-only blocks. The verified code is the shipped code.
- Verified kernel candidates: the bounded `Reader`, checked u64 range math, the sorted interval map (memory blocks, symbols) and the undo log. Annotated items use no traits, `dyn`, closures, `HashMap` or `fmt`.
- Provable API shapes: half-open ranges with `start < end` and `Option`/`Result` in place of panics. Also `v.set(i, x)` in place of index assignment, pairwise `i < j` invariants and closed spec fns for private fields.
- One std-only `xtask` binary for agents: `xtask cov` (llvm-tools, summary JSON, per-crate gate), `xtask verify` (Verus if present, else `{"status":"skipped"}`), `xtask ste` (comment lint) and `xtask fuzz <target> --iters N --seed S`. Every command writes JSON to stdout.
- Root `Cargo.toml`: `resolver = "3"`, edition 2024, the tested `[workspace.lints]` tables, `unexpected_cfgs` with `check-cfg = ['cfg(verus_only)']`, rustdoc `broken_intra_doc_links = "deny"`. `rust-toolchain.toml` pins 1.97.0 with clippy, rustfmt and llvm-tools.
- A dev-only `testkit` crate (zero external dependencies): SplitMix64 with known-answer tests, Lemire `below`, `check`, `shrink`, `mutate`, `fuzz`, AFL edge values and replay of `tests/regress/*.bin`.
- Parsers take a byte budget, a fuel limit and a recursion limit, and report each as a typed error. `catch_unwind` cannot catch a stack overflow or an abort, and the fuzz loop cannot stop an infinite loop.
- Docs and comments obey STE and a project GLOSSARY of technical names (xref, basic block, P-code, VA, RVA) and verbs (parse, decode, disassemble, lift). Tool descriptions and error hints use the same rules.
- Temporary prototypes from the research session are not in the repo. They are in `/tmp/claude-0/-home-user-ghidorah/240e3b55-981d-585e-9558-61cffd086307/scratchpad/` with `vproofs/` (4 Verus proofs), `hy2/` (hybrid pattern), `pbt/src/lib.rs` (harness) and `vb/verus/` (built Verus and z3).
- Tests: plain tests and property tests first, then the Verus spec. Keep one buggy copy per kernel in `verify/negative/` that must fail. Gates: coverage ≥ 90% lines and ≥ 80% regions on core crates, `CARGO_BUILD_WARNINGS=deny cargo clippy --workspace --all-targets`, `cargo fmt --check` and `cargo doc` with deny. Also the STE lint and 10k fuzz iterations per parser with a fixed seed.

#### Pitfalls

- Any Cargo dependency on `vstd`, also optional or dev, breaks the zero-dependency rule.
- Pin the Verus commit and its toolchain (1.98.1). It differs from the project toolchain (1.97.0).
- `#[cfg_attr(verus_only, verus_spec(..))]` on methods fails without a real `#[verus_verify]` on the struct and the impl.
- Do not gate exec code with `cfg(verus_only)`. The verified code and the shipped code then differ, which is unsound.
- Run Verus with `--no-cheating` for project code. `assume` and `external_body` make the trusted base larger without notice.
- Coverage: RUSTFLAGS must be identical in the test run and in the `--no-run` object listing. Use a separate `CARGO_TARGET_DIR` and an absolute `LLVM_PROFILE_FILE`.
- The rustup directory override covers only `/home/user`. Scripts elsewhere use `stable`, which has no llvm-tools. Pin with `RUSTUP_TOOLCHAIN` or `rust-toolchain.toml`.
- clippy and rustfmt can be missing in a fresh container. The setup script runs `rustup component add clippy rustfmt llvm-tools`.
- `panic::set_hook` is global and races with parallel tests. Run fuzz tests in their own test binary or with `--test-threads=1`.
- `arithmetic_side_effects` and `indexing_slicing` are noisy in address code. Use `#[expect(.., reason)]` per item, never a crate-wide `allow`.
- Do not copy the ASD-STE100 dictionary into the repo. A regex STE checker gives false positives, so review its output.

- The research stream for this topic finished, but a safety classifier withheld its result. It contains no findings and no sources.
- Do not use this topic as evidence for any acceptance criterion.
- Design implication: the planning phase designs two items from first principles. The first is the composition mechanism (batch or query grammar, budgets, error shape). The second is the offline agent-quality harness (tasks, metrics, thresholds). ## 4. Agent UX principles (merged)

1. **One registry, many front-ends.** CLI, MCP stdio, JSONL batch and `describe` come from one table. `tool_search` gives names, then summaries, then full schemas.
2. **Few merged tools.** Use about 15-25 `resource_verb` tools with underscores. Put search keywords first in each description. Offer read-only and mini profiles.
3. **Explicit annotations.** Set `readOnlyHint`, `destructiveHint`, `idempotentHint` and `openWorldHint` on every tool. Analysis tools are never open-world.
4. **Determinism.** The same input gives byte-identical JSON. Sort every map. Run analysis single-threaded in a fixed order. `tools/list` order is fixed.
5. **Stable IDs.** `binary_id` (SHA-256), function = entry address, `imp:`/`exp:`/`sym:`/`sec:` IDs, `OpId`, variable IDs from storage, transaction IDs and revisions. A rename never changes an ID.
6. **Address strings.** Output lowercase `0x` hex strings. Accept hex, decimal strings, symbols, `sym+0x10` and default names (`FUN_00401000`). Return the canonical address next to every name.
7. **No silent ambiguity.** An ambiguous name returns `AMBIGUOUS_NAME` with every `name @ addr` candidate.
8. **Bounded output.** Small default limits, a hard cap below about 40,000 characters, an opaque cursor, `total`, `truncated` and a narrowing hint. Offer count-only mode, field selection and concise or detailed formats.
9. **Composite tools.** `binary_survey` and a function context bundle (`include: [disasm, decomp, xrefs, strings, callers, callees]`) replace common call chains.
10. **Batch-first.** Tools accept one item or a list. Each item has its own result or error. One failed item never fails the call.
11. **Errors as data.** Two tiers. Stable UPPER_SNAKE codes. The message follows "What failed. Why. Action.". Add `hint`, `candidates`, `valid_example` and `retryable`. Parse errors give a field path and byte offset.
12. **Lenient input, strict output.** Coerce stringified arrays and numbers. Report coercions in detailed mode. Never loosen the published schema.
13. **Undoable edits.** Each mutation is one named transaction. `dry_run`, `expected_rev`, `history_list`, `history_undo` and `history_redo` exist. Each edit returns the new revision.
14. **Provenance.** Every fact has `{source, tx_id, agent/session}`. A priority guard blocks lower-rank overwrites with a structured error.
15. **Incremental context.** `changes_since{rev}` returns coalesced events, so agents refresh only what changed.
16. **Confidence and caveats.** Function starts show provenance and confidence. Decompiler output shows warnings with remedies. Unknown facts are `Unknown`, not guesses.
17. **Addressable views.** Disassembly lines carry addresses. Pseudo-C has a `line_map`. IR ops carry `OpId`. Canonical mnemonics are separate from display text.
18. **Persistent agent memory.** Bookmarks (TODO, Hypothesis, Finding, Error), notes and coverage metrics (functions analyzed, named, typed) survive context resets.
19. **Budgets.** `max_steps`, `max_ms` and `max_nodes` exist on long operations. A budget stop returns a resumable status. Long work uses a job handle and progress notifications.
20. **Verification hooks.** Raw IR views, pass switches (`--no-fold`), a recompile test and oracle diffs let an agent test a claim.
21. **Binary text is data.** Escape control characters, cap the length and return lossy `text` plus exact `hex`.
22. **Number helpers.** An `int_convert`/calc tool does base conversion and address arithmetic, so models do not compute hex.
23. **Clean channels.** stdout carries only protocol data. Logs go to stderr. The tool never prompts. A read-only mode exists.
24. **Short instructions.** Server instructions (2,000 characters or fewer) give the workflow `binary_load → analysis_start → func_list → func_get`, the address format, handle lifetimes and undo rules.

## 5. Risks and open questions

### 5.1 Risks

- **Scope.** The research covers three formats, three ISAs, a lifter, analysis, a decompiler, types, demanglers and a protocol. Mitigation: x86-64 ELF end to end first, then PE, Mach-O, AArch64 and RISC-V.
- **Missing research.** Section 3.11 is empty. Mitigation: design the composition layer and the evaluation harness in planning, with the Section 4 principles.
- **Hostile input.** OOM, infinite loops and stack overflow come from untrusted counts, cycles and recursion. Mitigation: `Limits`, fused iterators, visited sets, work budgets, depth counters, `catch_unwind` and worker threads with a fixed stack.
- **Oracle disagreement.** objdump and LLVM agree on only 42% of random inputs, and c++filt and llvm-cxxfilt differ on 1.9%. Mitigation: normalizers, structured comparison and reviewed allowlists.
- **Semantic bugs.** SLEIGH, VEX and angr tables all had bugs. Mitigation: native oracle, ptrace co-simulation, exhaustive fusion tests and N-version comparison.
- **Determinism regressions.** One `HashMap` iteration on an output path breaks golden tests. Mitigation: two-run byte-equality tests and a review rule.
- **Protocol churn.** MCP changed to stateless in 2026-07-28, and tasks and subscriptions changed. Mitigation: dual-era server, no dependency on tasks or `resources/subscribe`.
- **Licenses.** VEX and QEMU are GPL, Intel SDM and full Arm ASL are proprietary, radare2 data and glibc headers are LGPL, win32metadata keeps SDK header licenses. Mitigation: transcribe semantics, ship generators where the license is unclear, keep attributions.
- **Verus cost.** Toolchain 1.98.1 differs from the project toolchain, and the build takes about 7 minutes. Mitigation: optional job, hybrid pattern, recorded JSON results as evidence.
- **Coverage gaps.** Stable Rust has no branch or doctest coverage. Mitigation: line and region gates plus property tests.
- **Token cost.** Verbose JSON can cost more than compact text. Mitigation: measure with evals before the default is fixed.
- **Version-bound facts.** libc signatures and header prototypes depend on the glibc build and the data model. Mitigation: label every match with build, version and confidence.

### 5.2 Open questions

- **Storage.** Inverse-operation log or persistent structures for undo? Snapshot plus journal, text or binary? How do multi-program projects resolve externals?
- **Provenance.** Is AGENT equal to ANALYSIS (Ghidra AI=2) or above it? Does each agent session get its own source ID?
- **Address spaces.** Include overlays and the OTHER space in the first data model, or add them later with a migration?
- **Concurrency.** Keep analysis single-threaded, or allow parallel per-function work with a deterministic merge?
- **IR.** Is `Stack(k)` SSA with escape analysis in v1? May a Load move across a Store (alias rules)? What values do undefined flags get when they are materialized? Can `OpId`s survive a `lift_ver` change?
- **IR, continued.** Hand-written lifter match arms or table-driven specs? Float and SIMD semantics in v1, or `Intrinsic` with declared inputs and outputs? Are the 8 libc flag readers with no writer asm conventions or sweep misses?
- **Analysis.** Nucleus components or prologue patterns for gap fill? Is a strided-interval domain worth it for jump-table bounds? Is a `.cold` part one function with several ranges or a linked part entity?
- **Decompiler.** Which SAILR deoptimizations give the most goto reduction on the target corpus? What is the default token budget of the IR view? How deep is v1 type recovery? Is `for` recovery on by default? Which edits invalidate the decompile cache?
- **Decoders.** objdump or LLVM as the main x86 text reference? Full EVEX in v1? APX on by default? Const tables or a std-only `build.rs` generator? AArch64 SIMD/FP and SVE scope? Can CI run objdump and llvm-mc?
- **Formats.** Owned model or lazy model for very large binaries? One modern Windows loader profile or per-version rules? ARM64E and dyld shared cache scope? Stub naming by section names or by pattern scan? Symbol versions in import IDs?
- **Types.** May ghidorah ship tables derived from glibc headers and win32json? Accept clang as the only MSVC layout oracle? C++ class layout (vptr, bases, vbptr) in scope? Default demangle style: LLVM short or GNU? Worker process or fixed-stack thread for demangling?
- **Protocol.** Which MCP era do Claude Code and the Agent SDK send by default in October 2026? Does Claude Code show `content[]`, `structuredContent` or both to the model? Reject lone surrogates or replace them? JSON or compact text by default? Accept 2025-03-26 batch arrays or answer -32600? Always qualify handles with `binary_id`? Synchronous calls with progress or job polling?
- **Quality.** Is a first-party, std-only stub proc-macro crate acceptable under the zero-third-party rule? Does Verus run in CI or only locally? Which crates have coverage thresholds? Is the STE lint deny or warn? Is a sancov fuzz crate with `unsafe` acceptable?
- **Agent surface.** Is a small query or batch language better than explicit tools (Hex-Rays code mode reports about 20% fewer tokens)? Add Streamable HTTP after stdio?
